## 1. 判定方法と対象ビルド

文言上の技術的範囲への属否は、請求項ごとの全構成要件で判断する。
一つの請求項で一要件が欠ければ、その請求項の文言侵害は成立しない。
従属項は引用元の全要件を含むため、追加部分だけを見て充足とはしない。
逆に、狭い従属項を満たさないことから、広い独立項まで不充足とはしない。
[特許庁・権利侵害の説明](https://www.jpo.go.jp/support/ipr/kenrishingai.html)。

表の記号は、**○: 対応する実装を確認、×: 必須構成が欠ける、?: 解釈または外部事実が未確認**。
○はその行だけの技術的対比で、侵害成立の認定ではない。複合条件の一部だけ確認した行は?とする。
要件は読みやすく要約したものであり、権利範囲はリンク先の請求項原文を基準とする。
「似た機能がある」「明細書の実施例に同じ運動がある」だけでは○にしない。

| 対象 | 固定した条件 |
| --- | --- |
| 通常版 | 評価用featureなし。`Scroll`／`Pop`と`Sequential`／`Random`を含む。初期値だけで判断しない |
| 一覧 | 弾幕OFFで表示可能。ONでは一覧のLoaderを解除。データの履歴は保持する |
| 映像範囲 | 実映像矩形で描画をクリップ。未取得のアスペクト比では描画領域が0 |
| 投稿 | 現行の投稿欄とNXへの送信を含む。受信専用アプリとは仮定しない |
| 評価版 | 各featureで復活する機能を別記。通常版への判断をそのまま適用しない |

権利の存続・有効性、業としての実施、実施主体・提供行為、均等侵害・間接侵害は、この表とは別の検討軸である。

**○を異なる表示状態から集めただけでは、請求項全体の充足を認定しない。**
通常版では、安定した表示状態について次が成立する。

| 弾幕設定 | 一覧の描画 | 移動コメントの描画 |
| --- | --- | --- |
| OFF | 実況ページを開けば生成される | Loaderが解除される |
| ON | 実況ページを開いても生成されない | 再生・コメント受信等の条件を満たせば生成される |

この排他制御がある事実は確定している。「同じバイナリーに両機能がある」だけでは判定しない。
一方、公報の文言に明示的な同時性がないことだけで、逆に「排他でも充足」とも判定しない。
両公報の説明段落0020には一覧を隠す実施例があるが、これは弾幕との排他制御まで記載したものではない。
実施例の図を請求項の必須限定として追加することもしていない。

未確定の具体的な分岐は次のとおり。

- **同時に一覧と移動表示が成立する関係が必要**との解釈なら、通常版はその関係が不充足になる。

## 10. 均等侵害・間接侵害は別の評価

### 均等侵害

文言不充足を「似ているので危険」と置き換えない。均等の成立には次の五要件を個別に検討する。
[特許庁・均等論](https://www.jpo.go.jp/support/ipr/qanda/q04.html)。

| 要件 | 今回の確認範囲 |
| --- | --- |
| 相違部分が発明の本質的部分ではない | 各発明の本質を認定する審査経過・先行技術の精査は未実施 |
| 置換しても目的を達し、同じ作用効果を奏する | 通常配置は重なりを許容し、外側クリップは外側表示を実現しない。元の構成との作用差がある。五要件を肯定する根拠にはしていない |
| 製造等の時点で置換を容易に想到できる | 当業者の知識・技術水準の証拠調査は未実施 |
| 出願時の公知技術と同一または容易に推考できる構成ではない | 先行技術調査は未実施 |
| 意識的除外などの特段の事情がない | 意見書・補正・訂正の精査は未実施 |

**今回、均等侵害の成立を裏付けた請求項はない。** これは均等侵害の不存在を確定したという意味でもない。
均等論があるという一般論だけで、文言上不充足の項を「充足」や「高リスク」へ変更しない。

### 間接侵害

特許法101条の該当類型ごとに、供給される物・プログラム、業としての行為、専用品か、
非専用品なら不可欠性・一般流通品の除外・必要な認識等を検討する。
アプリがシステムの一部であるだけでは成立としない。
[特許庁・間接侵害](https://www.jpo.go.jp/support/ipr/qanda/q05.html)、
[特許法101条](https://laws.e-gov.go.jp/law/334AC0000000121)。

今回の対象はソースの構成であり、具体的な販売・公開・配布、利用者が構成するシステム等の証拠は収集していない。
また、端末・プログラムの直接侵害が問題となる請求項と、システムへの部品供給を区別する。
**今回、間接侵害の成立を裏付けた行為はない。** 単なるフラグの存在から間接侵害とは判断しない。
