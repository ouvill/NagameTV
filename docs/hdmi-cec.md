# HDMI-CECリモコン操作（実験的）

Linuxで、HDMI接続したテレビのリモコンからながめTVを操作できます。Linuxカーネルが
HDMI-CECのリモコンメッセージをキー入力に変換します。ながめTVのウィンドウにフォーカスが
ある間は、キーボードと同じ操作に使えます。転送されるキーはテレビの機種や設定によって異なります。

## 対応環境

- テレビでHDMI連動機能を有効にし、ながめTVを接続したHDMI入力を選びます。LGでは
  この機能をSIMPLINKと呼びます。
- LinuxのCECアダプター `/dev/cecN` に、論理アドレス設定（`CEC_CAP_LOG_ADDRS`）と
  リモコン入力（`CEC_CAP_RC`）の両方が必要です。Raspberry Piでは `vc4-hdmi` が対応する
  HDMI出力を公開します。外付けアダプターは、Linuxが物理アドレスを設定できる構成で使います。
- 実行ユーザーにアダプターの読み書き権限が必要です。`ls -l /dev/cec*` で所有グループを、
  `id -nG` で現在のセッションの所属グループを確認できます。所有グループが `video` の場合は、
  `sudo usermod -aG video "$USER"` で追加してからログインし直します。
- deb版とAppImage版にはホストのデバイス権限が適用されます。snap版はインターフェースの
  [手動接続](snap.md#hdmi-cecを試す)が必要です。現行のFlatpak版はCECデバイスを公開しません。

## 有効化と設定

1. 「設定 → リモート操作 → テレビのリモコン（HDMI-CEC）」で操作を有効にします。既定値はOFFです。
2. 「CECデバイス」は通常「自動」を使います。自動で初めて選ぶときは、物理アドレスを取得済みの
   アダプターを優先します。複数のHDMI出力やアダプターがある場合は、テレビをつないだ
   `/dev/cecN` を指定できます。
3. 設定欄を表示すると、有効なアダプターの状態を読み直します。USBアダプターを後から接続した
   場合やアクセス権を変更した場合は「再検索」を押します。

通常起動では `settings.toml` の `hdmi_cec_enabled` と `hdmi_cec_device` を保存・復元します。
デバイスの空文字列は自動選択です。`--features=hdmi-cec` で起動すると、その起動に限って
有効になります。他の機能と併用するには `--features=epg,subtitles,hdmi-cec` のように指定します。
`hdmi-cec` を含まない許可リストで起動すると、設定画面からの有効化も制限されます。

## 論理アドレスの設定と解放

未設定のアダプターを見つけた場合、ながめTVは `NagameTV` という名前で、CEC 1.4のPlayback
デバイス（ベンダーID `0x000c03`）を登録します。登録時に
`CEC_LOG_ADDRS_FL_ALLOW_RC_PASSTHRU` を有効にし、デバイスを閉じます。登録はカーネルに
残り、テレビの電源やHDMI接続の変化に応じて、カーネルが論理アドレスを取得し直します。
ながめTVからテレビへの入力切り替えや電源操作は、この機能の対象外です。

`$XDG_RUNTIME_DIR/nagametv/hdmi-cec/` の `cecN.owner` にデバイスパスとアダプター名を
記録します。通常終了、OFFへの切り替え、別のデバイスへの切り替えでは、印と現在の設定が
一致する場合に論理アドレスを解放します。別の設定に変わっている場合は、印だけを削除します。
Linuxでは `SIGTERM`、`SIGINT`、`SIGHUP` を受けると、ウィンドウを閉じるときと
同じ終了処理を行います。終了要求の後にこの3つのいずれかを再び受けると、直ちに終了します。

`SIGKILL`、終了中の再シグナル、Waylandコンポジターの先行終了では、論理アドレスの解放を
完了できない場合があります。設定と印が残っていれば、次に有効化したプロセスが引き継ぎます。
電源が切れた場合は解放処理を実行できません。OSの再起動時にカーネルの設定と実行時ディレクトリの
印が消えます。
`XDG_RUNTIME_DIR` が設定されていない場合も登録はできますが、自動解放できないことをログに記録します。

### PiキオスクでOS側が設定する場合

[Piキオスク](pi-appliance.md)など、OSと一緒に配布する場合は、キオスク起動前に
systemdの `Type=oneshot` ユニットなどで次のコマンドを実行できます。対象はテレビをつないだ
アダプターです。コマンドには対象デバイスを読み書きできる権限が必要です。

```sh
cec-ctl -d /dev/cec0 --playback --osd-name NagameTV
```

`cec-ctl` は既定でキー転送を有効にします。OS側の登録でキー入力が届くため、アプリの
CEC設定はOFFのままでも使えます。ONにした場合も「既存のCEC設定を使用しています」と表示し、
終了やOFFへの切り替え後もOS側の登録が残ります。

## 状態表示

| 状態 | 表示の意味と対処 |
| --- | --- |
| `disabled` | 設定がOFF、または起動時の許可リストに `hdmi-cec` が含まれていません。 |
| `unsupported` | Linux以外で実行しています。 |
| `no-device` | CECデバイスが見つかりません。アダプターを確認して「再検索」を押します。 |
| `permission-denied` | デバイスにアクセスできません。実行ユーザーの権限を確認します。 |
| `no-remote-control` | アダプターに `CEC_CAP_RC` がありません。 |
| `configured` | ながめTVの設定をカーネルが受け付けました。物理アドレスが取得済みなら `2.0.0.0` のように表示します。 |
| `external` | 既存の設定を使用しています。キー転送が無効な設定では、リモコンのキーが届かない場合がある旨を表示します。 |
| `error` | 設定または解放に失敗しました。画面の詳細と標準エラー出力のログを確認します。 |

`configured` はカーネルが設定を受け付けた状態です。テレビの電源が切れていて物理アドレスが
無効でも設定でき、物理アドレスが有効になった時点でカーネルが論理アドレスの取得を始めます。
[Linux CEC uAPI](https://docs.kernel.org/userspace-api/media/cec/cec-ioc-adap-g-log-addrs.html)
[カーネル側の論理アドレス処理](https://github.com/torvalds/linux/blob/v7.0/drivers/media/cec/core/cec-adap.c#L1697-L1730)

## キー割り当て

方向キーで項目を移動します。キー入力はウィンドウ内の通常のキーボード操作に従います。
Pi 4とLG 43UN8100PJAの組み合わせでは、方向・決定・戻る・カラーキーがLinuxの入力イベントに
変換されました。数字とチャンネル上下はテレビ側が処理しました。
[実機調査](hdmi-cec-redesign.md#実機で確認したこと)
[カーネルからQtへのキー変換](hdmi-cec-redesign.md#キー入力)

### キーが届かないとき

テレビのHDMI連動設定、選択中の入力、ながめTVのフォーカスを確認します。

`cec-ctl -d /dev/cec0` でアダプターの能力、論理アドレス、キー転送フラグを確認できます。
テレビがCECメッセージを送るか調べるには、`cec-ctl -d /dev/cec0 -M -r` で監視しながら
方向キーなどを押します。`-M` に対応していないアダプターでは `-m` を使います。

## 実機検証が必要な項目

フェイクアダプターで所有の判定、再検索、設定の保存・復元と解放を検証します。実験扱いを
解除する前に、Piや対応USBアダプターと実テレビで次を確認します。

1. テレビを消した状態で有効にし、テレビを入れてから方向・決定・戻る・カラーキーが届くかを
   確かめます。入力切り替え、テレビの電源入れ直し、HDMIの抜き差しでも繰り返します。
2. OFFへの切り替え、通常終了と再起動、強制終了後の再起動、別アダプターへの切り替えで、
   論理アドレスの設定と所有の印が期待どおりに更新されるかを確かめます。
3. OS側で同じ識別情報を設定してから有効にし、再検索、OFF、通常終了を経ても
   OS側の設定が保持されるかを確かめます。

Workshopでは `python3 scripts/test.py startup -- signal-quit` が、分離 Wayland セッションで
ながめTVを起動し、3種類のシグナルで通常終了処理が実行されることを確認します。

関連する操作は[ショートカットとウィンドウ操作](shortcut-actions-design.md)と
[遠隔操作API](remote-control.md)を参照してください。
