# GitHub公開用の紹介素材

完成素材は[`docs/media/`](media/README.md)にあります。READMEの冒頭に視聴画面、
チャンネル一覧・番組表の画像を配置しています。

## 用途

| 素材 | 掲載する場所 |
| --- | --- |
| `live.png` | READMEの主画像、紹介記事の冒頭 |
| `channels.png` | 番組を見ながらの選局を説明する箇所 |
| `guide.png` | 番組表の説明 |
| `guide-details.png` | 番組表から番組詳細を開く説明 |
| `recording.png` | TS録画の一時停止・シークの説明 |

今回はスクリーンショットのみを掲載します。字幕や実況コメントは撮影に含めていません。
素材のクレジットは[ギャラリー](media/README.md#素材とクレジット)を参照してください。

## 公開用の説明文

GitHubのAbout欄:

> Mirakurunのライブ視聴・番組表・TS録画再生に対応したLinux向けテレビアプリ。Rust + Qt / QML。

Releaseや紹介記事の書き出し:

> ながめTVはMirakurunのテレビ放送とローカルのTS録画を再生するLinux向けアプリです。
> 7日分の番組表、字幕表示、NX-Jikkyoの実況コメントに対応しています。

## 撮影条件

- 2026-09-19、アプリのコミット `d2c6d3dfd031225a7c7b293fae323ba54d74f0cc` を撮影。
- 製品の`build/nagametv`と`Main.qml`をそのまま使用。製品コードの変更はありません。
- UbuntuのWorkshop、Qt Quick / GStreamer、NVIDIA GeForce RTX 4070 Ti。
- [専用GUI環境](gui-test-environment.md)で画面・実GPU・仮想音声を検証してから起動。
- 1440×810、日本語UI。設定・キャッシュ・音声出力は専用セッション内に隔離。
- Mirakurun形式の撮影用HTTP配信元はloopbackだけで待受。
  架空の8局（地デジ6局・BS2局）に同じオープンムービーを配信します。
  局ロゴ・番組表・TS内の番組情報は撮影スクリプトが生成します。
- 番組表は局ごとに開始時刻・番組尺を変え、短い案内枠、25〜55分の情報・教養番組、
  90〜110分の映画、地域スポーツ中継などを編成しています。
  字幕・再放送の表記、話数・特集内容も架空の番組データの一部です。
  番組表とTS内の番組情報には同じ開始時刻・終了時刻・タイトルを使います。
- ライブ振り返りの保存とコメント受信は撮影設定でOFF。外部の実況サービスには投稿しません。
- 専用音声出力への再生を検証してから撮影します。

## 再撮影

通常のアプリビルド・GUIテスト環境に加えて、紹介素材作成用の**FFmpeg**
（原素材をTSに変換する`ffmpeg`）、**ImageMagick**（`import`）、
**xdotool**が必要です。これらは素材作成用の追加ツールで、通常のビルドには不要です。
日本語UIには既存のNoto Sans CJKを使用します。

リポジトリーのルートで実行します。

```sh
# 通常の開発手順でビルドする
cmake -S . -B build
cmake --build build

# CPUのみ。公式アーカイブを取得・検証して、78秒から120秒分のTSを作る
python3 scripts/publicity/prepare.py

# 専用画面・実GPU・仮想音声を自動検証し、撮影・画像の配置まで行う
bash scripts/capture-publicity.sh
```

最初の取得は約188 MiBです。原素材・中間TS・ログはGit管理外の
`build/publicity/`に保存します。完成素材は`docs/media/`の同名ファイルを置き換えます。
準備スクリプトはアーカイブのSHA-256を検証します:

```text
dc24016805203e5ae750f19cbd616e20561664d5bf5755ae484e3ed5487824b2
```

撮影スクリプトはLinuxのX11入力と画面取得に依存します。ホストの画面には接続せず、
既存の専用セッションランチャーを使います。必要な機器・コマンドがなければ停止し、
ソフトウェア描画へ切り替えません。素材準備のCPUエンコードは、
アプリのGPU描画とは独立した処理です。

撮影は実時間なので、映像の瞬間と時計表示は毎回少し変わります。
UIの配置やアニメーション時間を変更した後は、画像5枚を見て、読み込み中表示・
ツールチップ・意図しないダイアログ・文字切れがないことを確認してください。
撮影結果はUI回帰テストの代わりにはなりません。

番組の編成・説明文は`scripts/publicity/schedule.py`、局名・撮影操作は`capture.py`、
TSへの番組情報の書き込みは`fixture.py`にあります。
