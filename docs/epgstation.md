# EPGStationの録画一覧・再生

右上の「録画」から、サーバー上の録画を検索して再生できます。
Mirakurunの接続設定は不要です。

録画一覧はウィンドウ全体を使う独立した画面です。右上からライブ・番組表・設定へ移動できます。
左上の戻るボタン、戻るキー、または`Escape`で視聴画面へ戻ります。一覧を開いている間も再生は続き、
一覧を開き直すと検索欄、ページ、スクロール位置を保持します。アプリの再起動後は復元しません。
ローカルファイルや録画URLは、一覧上部の「動画ファイルを開く」「URLを開く」から指定できます。
`Ctrl + O`からファイル選択・URL入力を開くこともできます。

方向キーでは、検索欄から下で録画一覧、上で「動画ファイルを開く」などの操作へ進みます。
録画行は上下で選び、画面外へ進むとスクロールします。Enterで再生し、複数ファイルがある場合は
ファイル選択を開きます。録画中などの再生できない行も理由を読めますが、Enterでは再生しません。
最終行から下でページ送りへ進み、左右で「前へ」「次へ」を選びます。
方向キーでページを切り替えた後は、取得したページの先頭行から選べます。

検索欄と録画URL欄は、方向キーで選んだ時点では文字を編集しません。Enterで編集を始め、
編集中の左右キーは文字カーソルの移動に使います。検索欄で再びEnterを押すと検索し、
URL欄では動画を開きます。新しい検索結果は先頭行から選べます。
戻る・Escは入力内容を残して編集だけを終え、次に押すと画面を閉じます。
マウスクリックやTabで入力欄へ移った場合は、そのまま入力できます。
ファイル選択から戻ると、元の録画行にフォーカスが戻ります。

## 接続する

1. 設定の「接続」を開き、「EPGStation接続」にURL（例: `http://epgstation:8888`）を入力します。
   録画一覧の「接続先…」からも、この欄へ移動できます。
   サブディレクトリーで公開している場合は、そのパスも含めます。末尾の`/api`は付けません。
2. 認証なしの場合は「接続する」を選びます。stuayu版で認証を使う場合は「ログイン…」を選び、
   ユーザー名とパスワードを入力します。
3. 一覧の取得に成功すると接続先URLを保存します。「録画一覧を開く」で一覧へ戻り、検索欄でキーワードを指定し、
   「前へ」「次へ」で50件ずつ移動できます。キーワードの検索対象・並び順はサーバーの仕様に従います。
4. 番組の行をクリックするか、行内の「再生」を選びます。ファイルの形式検査に成功すると録画一覧を閉じ、視聴画面へ移ります。

URLとログインの操作は設定の「接続」にまとめています。録画一覧には検索・ページ移動・再生を置きます。
接続先の変更やログインでは検索条件をリセットします。入力途中のURLは設定内のカテゴリを移っても保持し、
設定を開き直すと保存済みのURLに戻ります。

パスワード、セッションCookie、再生トークンは設定ファイルへ保存しません。
認証状態はアプリ起動中に保持し、再起動後は再度ログインします。別の接続先へ切り替えた場合も
認証情報を引き継ぎません。通信エラーや認証エラーで一覧を取得できなかった接続先は保存しません。
設定の保存に失敗した場合は画面にエラーを表示します。

[番組表からの録画予約](recording-reservations.md)がONの場合は、保存済みの接続先を起動時に
資格情報なしで確認します。予約をONにしたときと、未確認のまま番組表を開いたときにも確認し、
同時に複数の確認を送らず、定期的な再試行は行いません。認証不要のサーバーなら録画画面を
開く前から予約できます。認証が必要な場合は設定からログインしてください。
確認結果は録画画面の表示・検索条件・保存設定を変更しません。失敗はログに記録します。

## 対応範囲

| 接続先・機能 | 対応 |
| --- | --- |
| 本家EPGStation v2の共通API | 認証なしの録画一覧・検索・録画済み動画の再生 |
| stuayuフォーク版 | 共通APIに加え、ユーザー名・パスワード認証と外部プレイヤー用トークン |
| 再生 | 録画が完了した、サイズが0より大きいTS・エンコード済みファイル。サーバーのHTTP Range対応が必要 |
| 録画中・動画ファイルなし | 一覧に再生できない理由を表示 |

録画一覧で上下キーを押して録画を選び、決定またはクリックですぐ再生します。再開できる位置が
保存されている場合はそのファイルの続きから、再開位置がない場合は元TSを優先して再生します。
右キーまたは録画行の「…」で操作パネルを開き、「最初から再生」「再生するファイルを選ぶ」
「番組詳細」を選べます。「最初から再生」の表示は、再生途中の録画で使います。
番組詳細では番組名・放送局・放送日時と説明の全文を確認できます。
上下キーで項目を移動し、決定で実行します。戻る・Esc・左キーでパネルを閉じると、同じ録画に戻ります。

ファイル選択では元TSまたはエンコード済み動画を選びます。元TSを先に並べ、同じ種別内ではAPIの順序を保ちます。
ファイル名とエンコード設定名を表示し、選択をキャンセルしても現在の再生は続きます。
一覧の再取得中もファイルを選べます。同じ接続先の同じ録画が更新後の一覧に残っていれば、
選択画面を開いたまま最新のファイル一覧へ置き換えます。録画や再生可能なファイルがなくなった場合、
接続先・認証・ページ・検索条件を切り替えた場合は、選択画面を閉じます。

MP4・MKVの入力に対応します。中身の映像・音声は利用環境のGStreamerデコーダーで再生し、
必要な映像・音声デコーダーがなければ形式を含むエラーを表示します。ローカル・HTTP入力とも
シーク・一時停止・倍速・停止後の再再生を共通の操作で扱います。
[一般動画の再生と制約](recording-playback.md#mp4mkvの再生)も参照してください。

録画予約は[既定OFFの実験機能](recording-reservations.md)として提供します。
録画中の追いかけ再生、SSO、リバースプロキシ独自の認証、視聴履歴の同期は
未対応です。TSの字幕・実況には既存の[HTTP録画再生](recording-playback.md#epgstationの録画url)を
使います。一般動画は[埋め込み・外部字幕と実況同期](recording-playback.md#一般動画の字幕)に対応します。
CMカットの補正は行いません。

### 録画を削除する

検証用の起動オプション `--features=recording-delete` で、録画の操作パネルに「削除…」が
表示されます。HDMI-CECも使う場合は `--features=recording-delete,hdmi-cec` を指定します。
起動オプションを指定した場合は、設定画面で接続先をそのセッション用に設定します。
リモコンでは一覧で録画を選び、右で操作パネルを開いて「削除…」を選びます。確認画面には番組名・放送局・
放送日時を表示し、最初は「キャンセル」にフォーカスします。「戻る」でも取り消せます。
矢印キーで「削除する」へ移動して決定すると、EPGStationから録画を削除します。削除は元に戻せません。

再生中・一時停止中の対象録画は、停止してから削除します。動画を開いている途中や、URLから開いた
動画の再生中も、削除を保留します。確認後、EPGStationから取得した番組名と開始時刻を照合し、
サーバーが録画中・保護中と報告した場合は削除を中止します。操作対象はEPGStation一覧の録画に限ります。
削除に成功すると一覧から消え、隣の録画にフォーカスが戻ります。失敗した場合は録画を一覧に残し、
確認画面にエラーを表示します。決定または「戻る」で画面を閉じられます。

## APIと所有関係

2026-09-23に参照したstuayu版のコミットは
[`26f56720722e61e66fc33fc0c4aacfd3d98913ba`](https://github.com/stuayu/EPGStation/tree/26f56720722e61e66fc33fc0c4aacfd3d98913ba)です。
ユーザー環境の「最新版」は更新されるため、ここでは調査対象をこのコミットに固定します。
本家版は[`5cf2ea383d37937eacecf424820dbd7a278d577e`の録画API](https://github.com/l3tnun/EPGStation/blob/5cf2ea383d37937eacecf424820dbd7a278d577e/src/model/service/api/recorded.ts)と
[型定義](https://github.com/l3tnun/EPGStation/blob/5cf2ea383d37937eacecf424820dbd7a278d577e/api.d.ts)の共通部分を使います。

- `GET /api/recorded?isHalfWidth=false&offset=…&limit=50&keyword=…`で一覧を取得します。
- stuayu版のログインは`POST /api/auth/login`、再生トークンの取得は`GET /api/auth/media-token`です。
  Cookieは接続先ごとのHTTPクライアントで管理し、API要求のリダイレクトには追従しません。
- `GET /api/channels`の明示的な`networkId`・`serviceId`を録画の`channelId`と照合します。
  放送局情報を取得できない場合は、動画を開いても実況の接続先を推測しません。
- 一覧に動画の`startAt`がない場合、`GET /api/videos/{videoFileId}/metadata`を検査ワーカーで
  取得します。Cookieは一覧と同じ接続に属し、キャンセル・接続先変更後の結果を混在させません。
- 再生は`GET /api/videos/{videoFileId}`を使用し、認証時は`token`クエリーを付けます。
  録画番組IDと動画ファイルIDを現在の一覧で照合し、URLをQMLへ公開せず録画ローダーへ渡します。

Qtに依存しない`epgstation::Library`が一覧、ページ、認証セッション、通信の状態、
ファイル選択の対象となる録画IDを所有します。選択状態はカタログ内のenumで表し、
ページ・検索・接続先・認証を切り替えてカタログを破棄すると、選択も破棄します。
通信中・取消し待ち・待機中をenumで分け、取消したJobの終了を確認してから次の要求を開始します。
一覧を正常に解析したときだけ生成できる`VerifiedEndpoint`を設定保存に使います。
予約用の匿名確認も同じ一覧要求・解析とHTTPクライアントの設定を使いますが、
取得したページを表示せず、放送局情報の補完も行いません。成功した接続だけを共有セッションへ
反映し、設定保存用の結果は返しません。確認のJobは一覧操作とは別のenumで所有し、
接続先変更やログインを受け付けると古い確認結果を破棄します。
`RecordingModel`と`VideoFileModel`は読み取り専用のQt投影で、番組ID・動画ファイルIDは文字列として公開します。

JSONの取得上限は4 MiB、1回のHTTP要求は10秒、接続は5秒で打ち切ります。
検索文字列は256文字までです。一覧の操作は再生中のセッションを変更せず、
「再生」を押してファイルの形式検査に成功したときに再生対象を切り替えます。

## 一覧再表示時のQML契約

`Player.refresh_epgstation() -> bool`は、最後に取得した一覧の接続先・検索語・
offset（ページ）・認証セッションを使って再取得する。QMLの検索欄にある未確定の文字列は
使わず、ページを先頭へ戻さない。要求を受け付けた場合は`true`を返す。
未取得、接続先なし、一覧の取得中・取消し待ちの場合は、要求も状態変更も行わず`false`を返す。
QMLは一覧を開く際に呼び、`false`の場合は従来の接続先・busyの条件に従って
`browse_epgstation(server, keyword)`による初回取得を行う。

受け付けると既存のエラーを消して`epgstation_busy`を`true`にする。
取得中も`epgstation_loaded`、表示中の行、件数、ページ、前後ページの可否を保持し、
一覧の移動・選択・再生を使える。ページ移動や新しい検索を受け付けた場合は、古い更新を
取り消してその操作を優先する。取り消した応答で新しい一覧を上書きしない。
通信・解析に失敗した場合は行・件数・ページを保ち、`epgstation_error`で原因を表示する。
失敗は処理時に一度ログへ記録し、`epgstation_busy`を`false`へ戻す。

成功時に、同じ`recordings: RecordingModel`の内容と、再生に使うカタログをまとめて
置き換える。削除によってoffsetが総件数以上になった場合は、最後の有効なページを
再取得してから反映する。総件数0の場合は1ページ目の空一覧とする。
この補正中も元の行を表示する。補正先の取得に失敗した場合は元の一覧を保つ。
補正先の再取得は1回までとし、その間にさらに削除されて補正先も範囲外になった場合は
エラーとして元の一覧を保つ。再取得中に総件数0になった場合は1ページ目の空一覧を反映する。

通知は既存のものを使う。

- 受付時と完了時に`epgstation_changed()`を通知する。通知ハンドラーから参照する
  busy・loaded・error・total・page・previous・nextとモデルは、その時点の結果にそろえる。
- 録画行の内容・順序・件数が変わった場合、`RecordingModel`は
  `beginResetModel`／`endResetModel`と`changed()`を使う。差分の行挿入・削除ではない。
  行を一度空にする通知は出さず、取得結果へ直接置き換える。
- 行が同じで視聴進捗・サムネイルだけが変わる場合は、既存の`dataChanged`と`changed()`を
  使う。同じ結果にはモデル通知を出さない。受付時や失敗時には録画行をリセットしない。
- ファイル選択候補の`recording_files: VideoFileModel`は、再取得の受付時・失敗時には保持する。
  再取得中に選んだ録画も、同じ接続先の同じ録画IDが新しい一覧に残る場合は、
  その行から取得した最新のファイル一覧へ直接置き換える。ファイルが同じならモデル通知を出さない。
  録画が消えた場合や再生可能なファイルがなくなった場合は、選択状態と候補を消去し、
  既存のモデルリセットと`changed()`で選択画面を閉じる。接続先・認証・ページ・検索の
  切り替えでも、受付時に選択を破棄する。候補の反映は`epgstation_changed()`より前に完了する。
  再生時は録画IDと動画IDを現在のカタログで照合し、古い動画IDを使わない。
  サムネイルと「続きから見る」の投影も既存のモデル通知で更新する。

QMLは更新前のスクロール位置と現在の録画ID（`recordedId`）を保存し、成功時の
モデルリセット後に復元する。同じ録画IDがなければ有効な行へ選択を補正し、スクロールも
新しい範囲に収める。最終ページへの補正で別のページになった場合も同様に処理する。
検索欄の内容と画面の移動履歴は変更しない。

`RecordingModel.row_for_recording(recorded_id: QString) -> i32`は、文字列の録画IDを
現在の行番号へ変換するinvokableである。一致する録画がない場合、空・不正なID・
`u64`の範囲外の場合は`-1`を返す。状態や通知は変更しない。
QMLはモデルリセット後に保存した`recordedId`を渡して選択を復元する。
64bitのIDをJavaScriptの数値へ変換しない。

## 検証

ローカルのHTTP応答を使うRustテストで、共通API、認証Cookie、再生トークン、
検索・ページ移動、接続先間の認証分離、取消し、遅延応答、HTTPエラー、不正なJSONを確認します。
接続テストではQtの一覧モデル、通知中の整合性、確認済み接続先の保存を扱います。
一覧の再取得では、検索語・ページ・認証の保持、取得中の行とページ移動、失敗時の保持、
最終ページの補正、遅れた応答の破棄、サムネイルの再取得をローカルHTTP応答で確認します。
PlayerとQAbstractItemModelTesterを使い、置換時のモデルリセット、同じ行の進捗更新、
録画IDからの行検索、通知時のモデル・ページの整合性も確認します。
起動テストでは製品の画面から録画一覧を開き、TS・MP4・MKVのHTTP再生へつなぎます。
複数ファイルからの選択・取消し、単一ファイルの直接再生、一般動画とTS間の切り替えを確認します。
録画画面から設定のEPGStation欄への移動と一覧への復帰、設定・番組表の切り替え、
URL入力の取消し、検索欄とスクロール位置の保持も確認します。
録画一覧で再生・選局のキーが背後の動画へ作用しないことと、`Escape`で画面を戻る操作は
QML部品テストで確認します。

```sh
python3 scripts/test.py app --filter 'test(epgstation::)'
python3 scripts/test.py connection
python3 scripts/test.py danmaku
python3 scripts/test.py startup
```

2026-09-24に、Rustテスト331件（除外5件）、QML部品テスト324件（対象外18件）、
接続・デスクトップメディア・起動テストの成功を確認しました。起動テストでは認証なしと
Cookie／再生トークンを使う接続の両方を再生し、640×360と960×540の画面を確認しています。
確認画像は`build/navigation-review/epgstation-*.png`へ出力します。

利用中の実サーバーへの接続確認は未実施です。APIの互換性を調べた範囲と、
実サーバーの設定を含めた動作確認は区別します。

### 固定版の実サーバーとの結合テスト

LinuxでDockerと通常のRustビルド環境を用意し、次を実行します。画面・GPU・音声・
チューナーは使いません。Dockerが使えない場合や起動に失敗した場合は検査を失敗させます。

```sh
CARGO_TARGET_DIR=build/cargo python3 -m scripts.testing.epgstation_integration
```

[固定したコミットとNodeイメージ](../tests/epgstation/provider.json)から、上流のlockfileを
使ってEPGStationをビルドします。専用コンテナーで本体のDBマイグレーションとHTTPサーバーを
実行し、認証なしのルートと、`/protected`以下の認証付きAPIへ製品のRustクライアントで接続します。
ポートはループバック上で自動割当てし、HTTPで準備完了を確認します。テストの再試行は行いません。
終了時にはこの実行で作ったコンテナーとネットワークを削除します。

検査する内容は次のとおりです。

- ログイン、Cookie、再生トークン、認証拒否、接続先の切り替え。
- 録画画面を開く前の予約用匿名確認。認証不要なら共有セッションが成立し、認証必須ならログインまで未確認のままになります。
- 52件の録画からの検索・ページ移動、放送局の対応付け、動画メタデータ取得。
- 予約済み・競合・スキップ・録画中の一覧と番組詳細。予約追加・取消しの書込みは含みません。
- `/api/config`に宣言した2件のエンコード候補の取得と順序。エンコード処理は起動しません。
- TS・MP4・MKVの全体取得、単一バイト・末尾・不正範囲を含むRange要求と本文の一致。
- MP4・MKVを製品のファイルローダーで検査する処理。デコード・画面再生は含まない。
- ログイン本文の分割送信・途中切断後も、別の要求が完了すること。
- 削除専用のコンテナーで、登録したテスト録画の詳細取得と `DELETE /api/recorded/{recordedId}` を実行し、対象のレコードと動画ファイルが消えること。
- [保存した実応答](../tests/fixtures/epgstation/README.md)と新たな応答の一致、および起動用モックとの比較。

番組名・時刻・解析済みメタデータはテスト用に登録した値です。録画・EPG更新・エンコード処理は
起動せず、HTTPハンドラーや認証・DBモデルの差し替えは行いません。ここで検証するのは
固定したstuayu版の保存済み録画・予約参照APIです。本家版、他のコミット、MySQL、TLS・リバースプロキシ、
利用中のサーバー設定の検証とは区別します。

`/api/config`がIPCで取得する放送波の状態は、登録済みの局DBを使う上流の予約モデルに委ねます。
削除専用のコンテナーでは、専用の録画IDへの削除IPCも上流の録画管理モデルに渡します。
検査で扱うIPCをこの2種類に絞り、録画やEPG更新を始めるoperator本体は起動しません。

通常の`cargo test`ではDockerを使う5件を明示的に除外します。上のスクリプトとCIでは
その5件を必須で実行し、未実行やJSONの差異を成功扱いにしません。保存済みJSONは通常の
RustテストとGUI起動テストでも使います。更新方法と出典は保存先のREADMEを参照してください。
ビルド・サーバー・Rustテストのログと、成功時のコミット・イメージIDは
`build/epgstation-contract/run-*/`に残します。認証情報とトークン付きアクセスログは保存しません。
