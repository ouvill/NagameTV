# TS録画の再生

シーク・一時停止・TS由来の番組情報取得の実装計画は、
[ロードマップとチェックリスト](recording-seek-roadmap.md)を参照。
以下は現在実装されている動作を記載する。

ローカルTSファイルをファイル選択、Ctrl + O、ドラッグ＆ドロップから再生する。
右上はライブ・録画・番組表・設定の順に並ぶ。録画ボタンは現在ファイル選択を開き、
選択をキャンセルしても再生対象は変わらない。録画一覧の実装時にこの遷移先を差し替える。
ライブボタンは直前の選択局へ戻り、サーバー未設定なら接続画面を開く。
初回のMirakurun接続画面にもファイルを開く入口があり、サーバー未設定で利用できる。
一度に開くファイルは1つ。複数ファイルのドロップでは現在の再生を変更しない。
検証中も画面操作と現在の再生を継続できる。「キャンセル」、停止、選局で検証を取り消せる。
続けて別のファイルを開いた場合は、最新の要求だけを採用する。

## 対応範囲

- 188バイト形式のMPEG-TS。先頭4MiB以内に有効なPATが必要。
- 最初に完成した有効なPAT上の最小サービスIDを選択し、映像・音声とARIB字幕を同じサービスにそろえる。
  複数サービスを含むTSでのサービス選択UIは未実装。
- 映像・音声の対応形式はインストールされたGStreamerデコーダーによる。
- 音量・ミュート・音声トラック選択・字幕表示・スクリーンショットは既存の処理を使用する。
- 停止・ファイル終端後の再生は先頭から開始する。終端は正常終了として表示する。
- 一時停止、シーク、再生位置の保存、MP4、EPGStation連携は未実装。

録画再生中はライブ番組情報と実況コメントを表示・投稿しない。録画の番組情報抽出や
過去ログとの同期は今後の項目。ファイル名をタイトルとして表示する。
チャンネルを選ぶとライブ視聴へ切り替わる。以前の選択局や接続先を録画の情報で上書きしない。

## 実装と失敗時の扱い

`playback::recording::Recording`はローカルファイルの読み取りとPATを検証した値。
ファイルURLのエスケープを保ち、空白・日本語・`#`・`%`を含むファイル名を扱う。
ファイル終端後の再再生時にも読み取りとPATを検証する。
TSの構文・PSI再構成・PATの複数セクションの集約は`transport`モジュールで字幕解析と共有し、
録画の検証には字幕デコーダーもQtも使用しない。

検証は`recording::Loader`が所有する専用スレッドで行い、UIでは完了済みの結果だけを受け取る。
取消しは結果取得の権利を消費して`Stopping`へ移る。前のワーカーが終了してから次を開始するため、
連続操作でもワーカーは増えず、破棄した要求の結果が再生を開始することはない。
読み取りは最大4MiB、取消し確認は64KiBごとに行う。実行中のOSのファイル操作そのものは
移植可能な方法では中断できない。遅いストレージでは次の検証開始が待たされることがあるが、
UIとアプリ終了はワーカーを同期的に待たない。破棄後のワーカーはQtやPlayerを参照しない。

Qtの`open_recording`の戻り値は要求の受付を表す。`recording_loading`が検証中を表し、
`recordingOpened`が新規ファイルを開く処理の完了を通知する。取消し・置換した要求は完了通知を出さない。

`player::stream_state::Attempt`がライブと録画を区別し、録画にはHTTP再接続を適用しない。
選択対象は`State`自身が所有し、停止時も同じ状態型内に再再生対象を保持する。
再試行の権利は非公開の`LiveAttempt`フィールドで管理し、取り出した時点で消費する。
`Attempt`は複製できず、Qtへの対象名・録画判定・再生状態の通知は一つの更新境界に集約する。
前の再生を停止できた場合だけ、`playback::Stopped`を介して字幕世代と入力を置き換える。
ファイルが存在しない、読み取れない、有効なPATがない場合は置き換え前にエラーを返し、
現在の再生を維持する。デコード開始後の失敗は通常の再生エラーとして表示する。

録画再生も`playbin3`と同じ映像・音声出力を使う。リモートAPIは録画中の状態とファイル名を
公開し、Play／Stopで再再生・停止できる。新たなファイルを開く操作はデスクトップUIから行う。
ファイルのフルパスはリモート状態に含めない。
リモートのPlayも検証を非同期で受け付け、開始後の状態通知で結果を確認する。

## 検証

Rustテストはファイル検証、URLの往復、ファイル削除・破損、録画へのHTTP再試行禁止を確認する。
ワーカーの終了をテストから制御し、取消し後の成功結果の破棄、最新要求への置換、
ワーカーを待たない破棄、再試行権利の二重取得禁止も確認する。
接続テストはQt状態通知、起動テストは製品のMain.qmlへのドロップ、映像フレームと音声トラック、
サーバー未設定での再生、停止・再再生・正常終端、ライブへの切り替えを確認する。
テスト用TSは合成映像と無音AACで、放送の録画データは含まない。
起動テストの実行には表示・GPU・音声出力が必要。[開発手順](development.md)を参照。

Flatpak内でのファイル選択・ドロップによる読み取りは別途検証が必要。
パッケージのファイルアクセス権限については[Flatpakパッケージ](flatpak.md)を参照。
