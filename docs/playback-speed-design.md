# 録画・タイムシフトの再生速度変更

2026-09-21に実装。録画・タイムシフトの再生速度変更の仕様と検証範囲。
録画と、ライブから遅れたタイムシフト再生を0.1倍刻みで調節する。
速度の範囲、プリセット、追いつき判定の余裕時間は以下を初期値とする。

## GStreamerでの実現性

GStreamerはSeekイベントの`rate`で再生速度を指定できる。
現在位置を移動先にした速度変更も可能で、API上は1.1倍や1.2倍を指定できる。
[公式の再生速度チュートリアル](https://gstreamer.freedesktop.org/documentation/tutorials/basic/playback-speed.html)

音声には`scaletempo`を組み込み、音程を維持してテンポを変える。
これはGStreamer Good Plug-insの`audiofx`に含まれる。
`scaletempo.rate`は読取専用であり、このプロパティへの代入で速度を変更するものではない。
[scaletempoの公式仕様](https://gstreamer.freedesktop.org/documentation/audiofx/scaletempo.html)

現在位置を変えずに速度を切り替える`INSTANT_RATE_CHANGE`もあるが、
すべてのパイプラインで使える機能ではない。本アプリでの対応は未確認。
初回実装は既存のフラッシュ付きシークを拡張し、短い再バッファーを許容する。
無瞬断の変更は別途検証後の改善とする。
[GStreamerのシーク仕様](https://gstreamer.freedesktop.org/documentation/additional/design/seeking.html)

## 操作UI

プレイヤー下部の左側に、文字だけの`x1.0`ボタンを追加する。
左側の並びは「音量、LIVE復帰（ライブのみ）、再生速度」とする。
中央の戻し・再生／一時停止・送りの位置は維持する。
ボタンの文字は常に小数1桁、非等速時は既存のアクセント色で示す。
ツールチップとアクセシブル名は「再生速度: 1.0倍」。

クリックするとボタンの上に調節パネルを開く。レイアウト概略:

```text
┌─────────────────────────────────┐
│ 再生速度                  x1.3  │
│  −   ━━━━━━━●━━━━━━━━━━━   ＋   │
│ 0.5                         2.0 │
│  x1.0    x1.2    x1.5    x2.0   │
│          等速に戻す             │
└─────────────────────────────────┘
       x1.3
```

- 範囲は**0.5〜2.0倍、0.1倍刻み**。0倍・逆再生は含めない。
  一時停止は既存の再生操作で行う。
- `−`／`＋`で0.1ずつ変更。端では該当ボタンを無効にする。
  プリセットは1.0・1.2・1.5・2.0倍。「等速に戻す」は1.0倍へ変更する。
- スライダーはドラッグ中に予定値を即時表示し、離したときに適用する。
  ボタンとキーボード操作は押すごとに要求する。
  連打中は実行中1件と最新の後続要求1件だけを保持する。
- 下部ボタンは適用確認済みの速度を表示する。処理中はパネルで
  「x1.3に変更中」のように予定値と受付状態を示し、成功後に両者をそろえる。
  失敗時はエラーをパネル内に表示し、未適用の値を現在速度として残さない。
- パネル外クリック、Escape、ボタンの再クリックで閉じる。
  閉じても適用済みの速度や受付済み要求は取り消さない。
  Escapeでドラッグを中断した場合は、その未確定値を適用しない。
- パネル表示中は操作部の自動非表示を抑制する。音量パネル等とは排他的に開き、
  選局・ファイル切り替え・停止で閉じる。閉じた後は起点ボタンへフォーカスを戻す。
- Tabでボタン・スライダー・プリセットを操作できる。スライダーの左右キーは
  速度変更に使い、既存の10秒戻し・30秒送りと二重に実行しない。
- 色、角丸、押下・開閉の動きは[UIデザイン方針](ui-design.md)に従う。
  文字だけでも通常42px高の操作領域を持たせ、数字の幅で配置を動かさない。
  狭い画面でも左側に残し、操作部の幅が620px未満なら2段配置へ移す。
  パネルは動画領域内に収め、サイドパネルの開閉にも追従する。

## 利用できる状態と速度の保持

| 状態・操作 | 動作 |
| --- | --- |
| 録画の再生中・一時停止中 | 0.5〜2.0倍を選べる。一時停止中に変えても再生を始めない |
| 遅れているタイムシフトの再生中・一時停止中 | 同じ範囲を選べる。保持済みTSを指定速度で消費する |
| ライブ位置付近 | 1.0倍固定。パネルに「ライブ位置では等速再生です。巻き戻すと速度を変更できます」と表示 |
| タイムシフト無効のライブ | 1.0倍固定。調節部を無効にし、利用条件を説明する |
| 索引・再生位置の準備中 | 調節部を一時的に無効にし、準備中と表示する |
| シーク・速度変更の処理中 | 新しい操作は後続の最新要求にまとめ、並行してシークを発行しない |
| 録画の正常終端 | 速度を保持。調節部は無効とし、再生ボタンで同じ速度で先頭から再生する |
| 停止中・再生対象なし | 速度ボタンを表示しない。次の開始時は1.0倍 |
| 選局・別ファイル・ライブへの切り替え | 新しい再生セッションは1.0倍 |
| 同一セッションでの一時停止・再開・シーク・音声選択 | 速度を維持する |
| 自動再接続・パイプラインを破棄する再開始 | 1.0倍へ戻す |
| 「ライブに戻る」 | 速度を1.0倍に戻し、現在のライブ復帰先へ移動して再生する |

速度はセッション内の状態とし、設定ファイルや別の録画へ引き継がない。
ライブ位置付近で遅い速度を選んで遅延を作る操作は初回の範囲に含めず、
巻き戻しまたは一時停止で遅れた後に調節する。

## ライブに追いついたとき

受信は常に放送の速度で継続する。倍速にするのは保持データの読み出し以降であり、
受信スレッド、保持容量、元TSの時刻を速度に合わせて変更しない。

最新位置は壁時計や番組終了時刻ではなく、共通TS入力が公開する受信済みの末尾を使う。
その末尾と、実際の出力から確認した再生位置を同じ時間軸で比較する。
アプリの`LiveBuffer`設定は受信末尾から残す予備時間として維持する。

- 1倍より速い再生がライブ位置付近へ到達したら、**自動で1.0倍へ戻す**。
  通常の自動復帰では現在位置で速度だけを変更し、最新位置へ追加のスキップをしない。
  適用後に「ライブに追いついたため、等速に戻しました」を一度表示する。
- 判定はRustに集約し、速度の操作可否・自動復帰・LIVE表示で共有する。
  従来の`ViewerActions.qml`の固定2,500ms判定を廃止し、Rustの判定を公開する。
  再生中は受信範囲を確認するたびに現在位置を問い合わせ、最大200ms前の表示用位置と最新の受信端を比較しない。
  「ライブに戻る」は、対応する出力Segmentとバッファーの到着を確認した時点でLIVE表示を確定する。
  復帰中にも進む受信端によって赤いLIVE表示へ切り替わらなくなることを防ぎ、後続の巻き戻しで上書きされた復帰は確定しない。
- 「遅れが設定の『ライブ再生の余裕』（`LiveBuffer`）以下」で等速へ戻す。
  初期値250msなら受信末尾から250ms手前が目標で、固定の余裕時間を加算しない。
  再生中に設定を変更した場合も、次の追いつき判定から新しい値を使う。
  追いついた後は、遅れが設定値より1,000ms以上大きくなるまで倍速を再び選択可能にしない。
  定数名に用途と単位を持たせ、境界付近の操作可否の往復を防ぐ。
- 別の音声・映像ストリームの時刻により受信末尾が先行し、設定値まで追いつけない場合も扱う。
  入力が受信待ちになり、かつ実際の再生位置が指定速度で進めなくなったら、供給可能な末尾への到達として等速へ戻す。
  入力の先読みだけでは判定せず、デコーダーに残る映像が倍速で進んでいる間は追いかけ続ける。
  観測時間は最低500ms、低い倍速では期待される追いつき量が200msになるまで延長する。
  シーク世代・速度の変更、一時停止では観測をリセットし、古い受信待ちを持ち越さない。
  目標の設定値に固定の余裕時間を加算するものではない。
- 復帰後に遅れが増えても、自動で以前の倍速へ戻さない。
  一時停止中は追いつき処理を実行せず、再開前に現在の保持範囲を再検証する。
- 受信停滞やバッファー不足でも等速へ戻し、追いつきとは別の理由で通知する。
  受信停止を録画の正常終端として扱わない。等速でも不足する場合は既存の
  バッファー待ち・通信エラーの処理に従う。
- 0.5〜0.9倍は遅れが増える。再生位置が保持範囲を失った場合は既存の期限切れ
  復帰規則で補正し、再生中なら1.0倍へ戻して通知する。
  一時停止中は既存仕様どおり停止映像を保ち、再開時に補正して1.0倍にする。

参考として、通常のライブ位置より10分遅れている場合、1.5倍では約20分、2.0倍では
約10分で追いつく。受信が進み続けるため、追いつく時間は概ね`遅れ / (倍率 − 1)`。
初回UIにはこの予測時間を追加しない。

## 映像・音声・字幕・実況の同期

シークバー、現在位置、番組情報、字幕、実況は元のメディア時刻を基準にする。
1.5倍で10秒再生すれば、表示位置は約15秒進む。
録画の総時間、10秒戻し・30秒送りの秒数は元映像の秒数のままとする。

音声は音程を保ち、速度変更を理由にミュートしない。主音声・副音声・音量・ミュートは
現在の選択を維持する。音声のない素材では映像だけで速度変更を成立させる。
初回は音声省略・キーフレームのみのトリックモードを使わない。

字幕の出現・消去、実況の出現・移動・表示寿命は再生位置に同期する。
既存の実況の「流れる速さ」設定は変更せず、メディア時刻の進み方で追従させる。
現在の実況エンジンにはメディア時刻モードがあるため、その時計へさらに倍率を掛けて
二重に加速しない。速度変更時のフラッシュで字幕・実況をリセットした場合は、
通常シークと同じ再取得・復元規則に従う。一時停止ではすべて止まる。

## 現在の実装との接続

| 対象 | 変更内容 |
| --- | --- |
| `rust/qml/PlayerControls.qml` | 左下の文字ボタンとレスポンシブ配置を追加 |
| 新規の速度パネル、`ViewerActions.qml`、`Main.qml` | 操作、フォーカス、パネル排他、自動非表示を既存の経路へ統合 |
| `rust/src/player.rs`、`player/transport.rs` | 適用済み倍率、要求中倍率、利用条件、失敗理由と変更操作を公開 |
| `rust/src/playback/session.rs` | 再生セッションと速度操作の寿命を一致させる |
| `rust/src/playback/timeline.rs` | 従来1.0固定だったSeek、後続要求、完了確認、ライブ復帰へ速度を組み込む |
| `rust/src/playback/input/source.rs` | appsrcのSeek／Segment／世代管理が非等速でも成立することを検証 |
| `rust/src/playback.rs`、`playback/audio_routing.rs` | 既存の主副音声フィルターと`scaletempo`を一つのaudio-filterへ構成 |
| 字幕・実況・デスクトップメディア連携 | 時刻追従を検証し、従来1.0固定だったMPRIS Rateと範囲を実際の状態へ更新 |

音声フィルターの候補構成は`audioconvert → DualMono → scaletempo`。
必要な音声形式変換はcapsの交渉に合わせて追加する。
既存の`audio-filter`を`scaletempo`単体で上書きして主副音声処理を失わない。
`scaletempo`はセッション開始前に組み込み、操作ごとに着脱しない。
プラグインがなければ等速再生を維持し、速度調節を無効にして理由を表示する。
Workshop・Fedora・AppImage・Flatpakの依存関係とプラグイン確認にも追加する。

### 状態と変更処理

- 倍率は非公開フィールドを持つ検証済みの`PlaybackRate`値として、整数5〜20で保持する。
  GStreamerへ渡す境界でのみ10で割る。UIの0.1の加算誤差を内部状態に持ち込まない。
- 利用条件は`Unavailable(reason)`／`LiveOnly`／`Variable`のようなenumで表し、
  操作可否や説明文をそこから導く。録画中などのboolだけで変更を許可しない。
- 現在の`TransportControl`と`Ready<'_>`の排他的な借用を拡張する。
  準備済みの再生位置・範囲・音声経路が確認できた操作だけが速度を変更できるAPIにする。
  QMLや外部連携からGStreamerへ直接倍率を渡さない。
- 後続要求は位置だけでなく「移動先・倍率・再開／一時停止・変更理由」を一組で持つ。
  速度変更中にシークしたら新しい移動先と最新の倍率を採用し、シーク中の速度変更では
  シーク先を維持する。倍率だけの後続要求は実行時の最新位置を使い、古い位置に戻さない。
- 適用は現在位置への`FLUSH | ACCURATE`付きSeekを基本とする。
  明示的なシークでも選択中の倍率を渡す。「ライブに戻る」は1.0倍と移動先を一緒に確定する。
- イベント送信の成功だけでUIを確定せず、同じセッション・操作番号に対応する
  出力Segmentとバッファーを確認する。映像と音声の`rate`／`applied_rate`は
  `scaletempo`によって表現が異なり得るため、意味上の速度と同期を検証する。
  一時停止中の完了はprerollで確認し、Playingへ移行させない。
- 拒否・タイムアウトでは変更失敗を通知する。以前の速度と位置が確認できれば継続し、
  適用状態を確認できなければ再生を一時停止してエラーにする。再開には等速への
  シーク成功を必要とし、速度が不明なままPlayingへ移行しない。
  UIの数値だけを戻して成功したように扱わない。
- 選局・停止後に届いた古い完了通知は破棄する。Qtには状態全体を更新してから通知する。
- MPRISからの速度変更も同じ検証・操作経路へ集約する。
  独自リモートAPIの速度操作追加や、新規のグローバルショートカットは別の拡張とする。

## 実装順と受入条件

1. 共通TS入力で0.5・1.1・1.5・2.0倍のSeekが伝わること、位置の進み方、
   `scaletempo`後の音程・同期を検証する。録画と保持済みライブの両方を対象にする。
2. 速度を含むtransport状態とQt公開境界を追加し、シーク・一時停止・連打・取消しを確認する。
3. 左下ボタンとパネルを組み込み、追いつき時の等速復帰・通知・字幕実況同期を確認する。
4. 配布依存関係とMPRISを整え、通常再生・既存の音声選択にも回帰がないことを確認する。

ハードウェア不要の試験では、倍率の境界、操作の併合、古い完了通知、状態通知中の整合性、
追いつき判定のヒステリシス、受信停滞と期限切れを確認する。
合成TSとメモリー出力による試験で、実時間に対するメディア位置の傾きと音声サンプルを測る。
これは機器を使わない明示的な試験であり、GUI／実出力試験の代替にしない。

実再生では次を受入条件とする。

- 録画・タイムシフトで0.1刻みを選べ、1.0倍に戻せる。
- 速度変更で意図しない数秒単位の巻き戻り、音声の継続的なずれ、終端の誤検出がない。
- 一時停止中の変更、連打、スライダー、前後シーク、音声切り替え、正常終端、
  PID変更・時計不連続の素材でも状態と表示が一致する。
- 追いつき時にバッファーを使い切る前に等速へ戻り、通知・速度変更を繰り返さない。
- 字幕と実況の出現・消去が映像に追従し、二重再生・二重加速をしない。
- 狭い表示・サイドパネル・全画面でボタンが重ならず、パネル操作中に操作部が消えない。

実装時は[開発手順](development.md)と[Qtテスト](qt-tests.md)のコマンドを使う。
GUI／音声検証は[専用GUI環境](gui-test-environment.md)で資源の検出・検証後に行う。
必要な表示・実GPU・音声がなければ、その試験を停止して不足資源を報告する。
設計時は静的確認のみだったが、実装では以下を検証した。

- ハードウェア不要のRustテスト289件成功、既存の任意試験5件はignored。
  共通TS入力で0.5・1.1・1.5・2.0倍の位置の進み方、停止位置の維持、シークと速度変更の併合を確認した。
  映像のみ、PID変更・時計リセットの素材でも一時停止を維持した速度変更を確認した。
  メモリー上のPCMで440Hzの音程維持と再生時間の変化も確認した。
  追いつき目標は「ライブ再生の余裕」の1・250・1000msの境界と、同じセッション中の設定変更を確認した。
  古い表示用位置による等速復帰漏れと、復帰中の受信進行によるLIVE表示漏れを修正前に再現し、修正後の成功を確認した。
  復帰後の巻き戻し、および復帰中に追加された巻き戻しがLIVE表示を上書きすることも確認した。
  音声PTSが映像より800ms先行する受信TSでは、250msの目標に届かず2倍速が残ることを修正前に再現した。
  修正後は実際のappsrc・demux・デコーダーを通じて等速復帰し、その後の再生とLIVE表示を維持した。
  入力先読み中の早すぎる復帰を防ぎ、1.1・1.2・1.5・2.0倍での供給不足の判定、古いシーク世代、
  一時停止・速度変更後の観測リセットも確認した。
- PlayerControlsのGUI試験18件成功。0.1刻み、プリセット、適用前後の表示、ドラッグの確定／取消し、
  キーボード、パネル排他、無効理由と非同期の失敗、狭い幅の重なりを確認した。
  QML全体も301件成功（評価用の旧コメント表示18件はスキップ）。
