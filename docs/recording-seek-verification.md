# 録画シークとTS番組情報の実装・検証

2026-09-16、`feature/recording-seek`。

## 採用方式

元ファイルを`playbin3`で読む。時間シークは`FLUSH | ACCURATE`を用いる。
`KEY_UNIT`では合成TSの30秒指定が27.599秒になったため、フレームを復号して指定時刻まで
クリップする方式へ変更した。独自のファイル全体インデックスや再多重化は導入していない。

要求は実行中1件と最新の待機位置1件に集約する。要求したseqnumの映像segmentとバッファー、
またはEOSを観測し、状態遷移を確認して完了とする。単独の`ASYNC_DONE`は完了条件にしない。
待ち時間は10秒。拒否は録画を維持して表示し、実行中のエラー・タイムアウトは既存の停止経路へ戻す。
失敗した停止では資源を保持する。EOFではセッションを保持し、再シークできる。

入力のflush、DISCONT、ファイルオフセットの飛びをストリーミング側で検出し、PAT/PMT、
continuity、PSI/PES断片、字幕デコーダー、PTS対応、番組情報を再取得する。
同じPAT versionへの巻き戻しもリセットする。字幕の管理情報・DRCSが移動先にない間は
旧字幕を再利用しない。追加の字幕用先行探索は実装していない。

SIは元TSで、選択サービスのPAT/PMTとPCRを確認して収集する。EIT actual p/f、SDT actual、
TDT/TOTを対象とし、EIT scheduleから録画範囲を推測しない。短形式・拡張イベント記述子、
コンテント記述子、サービス記述子を読む。拡張記述子は同一言語の全断片がそろった場合に結合する。
文字列はARIB STD-B24の指定・シフトを解釈し、既存libaribcaptionのUnicode表を使用する。
未対応のDRCS・モザイク文字は置換文字とする。新たな外部依存はない。

TOT/TDTは日本の放送のJSTとして解釈し、UTC epochへ変換する。映像PTSのstream time対応と
PCRを介して表示時刻へ写す。先読みした情報の即時表示、PCの現在時刻やファイル日時による
補完は行わない。日時未定はnull、番組情報なしはファイル名表示、TOTなしは進行率未確定として扱う。
情報取得は`--features=epg`、字幕解析は`--features=subtitles`に従い、単独でも動作する。

番組情報は1サービス・現在/次の2イベント、SI組み立ては5 PID、EITは最大4096バイト、
他の対応SIは最大1024バイト、表示待ち履歴は128件に制限する。満杯では新規履歴を捨て、
次の周期的なSIで更新する。字幕キューは既存の128件。全ファイルをメモリーへ保持しない。

## tsreadexとの比較

[tsreadex](https://github.com/xtne6f/tsreadex)の`a82528ccb698fcd07b4da1bb2243e63d685c34a7`を
一時ディレクトリーでビルドし、同じ合成素材を`tsreadex -n 1 recording-seek.ts`で整形した。
比較対象は元ファイルと整形結果を保存したファイル。両方とも同じCPUデコード・メモリーsinkで
PAUSEDのまま30秒→10秒→45秒→5秒を5周した。

| 条件 | 元TS | tsreadex整形後のTS |
| --- | ---: | ---: |
| サイズ | 1,692,940 bytes | 1,805,740 bytes |
| 検出長さ | 59.993秒 | 59.989秒 |
| 前後シーク | 20/20成功 | 20/20成功 |
| 出力フレームのstream timeの最大誤差 | 0 ms | 0 ms |
| 完了までの最大時間 | 8.22 ms | 14.24 ms |

これはキャッシュ済みの短い合成素材による機構の比較であり、実録画・低速ストレージの速度保証ではない。
映像/音声PIDの出入りはこの素材に含まれず、tsreadexの安定化効果の評価は未完了。
元入力でもこの受け入れ試験を満たすため、現段階では追加整形を採用しない。
tsreadexの`-s`は起動時のバイト移動であり、標準出力をパイプで挟むだけではファイルへの
ランダムアクセスを維持できない。必要になった場合は元オフセットと時刻の索引・プロセス再起動を
含めて設計する。整形により出力サイズが変わることも上の比較で確認した。

## 受け入れ試験

合成素材の指定位置との差は1.5秒以内、各操作の完了は5秒以内をCPU試験で確認する。
製品UI試験では各待機5秒の上限内で、一時停止中の45秒→10秒→35秒、20秒→40秒→15秒の
連続要求、終端到達、終端から5秒への移動を確認する。TS番組情報の1→2→1→2切り替えと
日本語タイトル・局名も実際のMain.qmlから検証する。

環境: Ubuntuコンテナー、GStreamer 1.28.2、X11、NVIDIA RTX 4070 Ti / OpenGL 4.6、
PulseAudio互換の音声出力。機器試験は各スクリプトで実機アクセスを検出・検証して実行する。
生成方法は[fixtures README](../tests/fixtures/README.md)を参照。

検証コマンド・最終結果は[ロードマップ](recording-seek-roadmap.md#検証記録)に記録する。

## 代表ケースの信頼性検証（2026-09-16）

今回はPAT/PMT再取得、同一サービス内のPID変更、時刻不連続、字幕管理情報・DRCSの
再取得に絞った。問題を再現し、小さな修正で収まる範囲までを対象とする。
tsreadex導入、PID固定、音声補完、字幕の追加先行探索、入力構成の作り直しは別作業とした。
滑らかさの対策も利用者の意向により見送りを継続する。

| ケース | 検証内容・結果 |
| --- | --- |
| 同じPAT/PMT versionへの巻き戻し | 成功。FLUSH_STARTで旧字幕キューを空にし、flush中の遅延入力とPAT/PMT再取得前の字幕を破棄。再取得後の新しい字幕だけをキューへ入れる。 |
| 字幕管理情報・DRCS | 成功。管理情報の同じdata-group IDを再受理し、字幕面を720×480から960×540へ更新。旧DRCS定義を使わず、再送された定義をデコーダーが取得する。 |
| 字幕PTSの巻き戻り | 成功。DISCONTの映像バッファーで旧表示待ち字幕を捨て、新しいPTSと映像時刻で表示を再開する。 |
| PCR/PTS/DTSの巻き戻りを含む録画 | 成功。3秒の合成素材を同じ時刻から再開する6秒のTSを製品Main.qmlで再生し、境界を越えて140フレーム以上を表示して正常終端へ到達する。 |
| 同一サービスのPMT・映像・音声PID変更 | **失敗・未対応**。PAT/PMT version更新後のストリームまで再生が進まない。下記の独立した再現試験に残した。 |

字幕試験はメモリー上のTS/PESと実際の解析器・libaribcaption・字幕時計を使う機器不要の試験。
任意のDRCSビットマップは既存のUIアダプターで描画できないため、この試験はその描画保証ではない。
定義があるときのネイティブDRCS文字と、未定義時の「〓」テキストセルを区別し、
古い定義の破棄と再取得を確認した。管理情報だけでは表示字幕を作らないことも確認した。

PID変更素材はサービスID 1を維持し、PMT PIDを`0x20`から`0x120`、映像/PCRを
`0x41`から`0x141`、音声を`0x42`から`0x142`へ変える。時刻は3.2秒進める。
素材のCRC、テーブル、サービス、PCR、境界の不連続フラグを別のRust試験で検証している。
生成方法は[fixtures README](../tests/fixtures/README.md#recording-recovery-fixtures)に記録した。

```sh
# 機器不要の回帰試験（178 passed / 3 ignored）
CARGO_TARGET_DIR=build/cargo cargo test --manifest-path rust/Cargo.toml --release --locked
# 機器を検証してから通常シーク・時刻不連続の録画再生を確認（成功）
bash scripts/test-startup.sh
# PID変更の既知不具合を再現（現時点では失敗、exit 1）
bash scripts/test-startup.sh recording-pid-change
```

素材の再生成ではSHA-256の一致を確認し、`cargo fmt --check`と`git diff --check`も成功した。
追加の`cargo clippy --release --locked --all-targets -- -D warnings`は、今回変更していない
`rust/src/transport/programs/syntax.rs:206`の`chunks_exact_to_as_chunks`警告1件により失敗した。

PID変更の再現試験は、5秒以内に90フレーム以上が描画されることを要求する。
前半は75フレームなので、前半だけ再生できても合格にはならない。失敗時には再生状態・位置・
映像統計・音声トラックを出力する。現環境では映像が前半で止まり、再生状態はPlayingのまま、
エラーは空だった。音声トラックは変更後のPIDを検出していたが、選択し直しても後半を再生できなかった。

切り分けでは製品UI・字幕処理を外した`playbin3`とメモリーsinkでも確認した。
PMT PIDを維持して映像/音声だけを変えた派生素材でも、前半75フレームでEOSとなった。
時刻の巻き戻り素材は149フレームで正常終端へ到達した。この比較から、PID変更の解消には
入力とストリーム切り替えの追加調査が必要と判断した。GStreamer全般で復旧不能とは断定せず、
今回の範囲では製品コードを変更していない。tsreadexでこの不具合が解消するかは未検証。

今回の検証は完了したが、「PID変更後も復旧するか明確なエラーで終わる」という条件は未達。
以下の追加作業と分けて、既知の制約として扱う。

## 残る検証・拡張

- 長時間・高ビットレートの実録画、ストレージ読み取り量、RSS/FD/スレッド数の連続測定。
- 放送切り替えによるPID/PMT変更、音声消失、破損・時刻不連続を組み合わせた再生比較。
- 字幕管理情報やDRCSが長く再送されない区間の追加先行読み取り。
- 番組情報の取得待ち・情報なし・解析失敗を分ける詳細な状態表示。
- Flatpakの実行・ファイル権限と他OS。未再現の放送切り替えフリーズは解決済みにしない。
