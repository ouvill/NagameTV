# 現在番組とEPGスナップショット

mainのviewer-core/epg.rsと現在番組のタイトル・時間・進行率・詳細表示を参照した。
EPG有効時は番組表を閉じていても選択局の現在番組を表示し、タイトルから説明を開ける。

## データと照合

`channels::BroadcastService` はnetworkIdとserviceIdのu16の組。
配信用のu64 IDとは別に保持し、チャンネルJSONの明示メタデータでEPGを照合する。
配信用IDの桁から放送局を推測しない。古いサーバーでメタデータが欠ける局は選局できるが、
その局のEPGは照合できないため現在番組は未取得表示になる。

`features/program_info/model.rs` がProgramとSnapshotを所有する。
番組名・説明はOption<String>で欠落とJSON nullを受け入れる。番組そのものの不在とは区別する。
全番組のVecを（networkId、serviceId、開始時刻、番組ID）順に並べ、重複を除く。
新たなHashMapや全番組の複製は保持しない。

局の先頭と末尾を二分探索し、その局の開始時刻を二分探索して現在番組を借用する。
mainと同様、開始時刻を含み終了時刻を含まない。重複時間帯では最新の開始時刻を選び、
それが終了していても古い重複番組を復活させない。ゼロ時間は現在番組にならない。
終了時刻の加算は飽和演算、進行率は有限の0〜1へ制限する。

既存の番組表も同じ局のスライスから表示データを作るため、他局の全番組は走査しない。
後続の移植で選択日（7日分）ごとの投影へ変更し、200件制限を廃止した。
日付と予定番組の詳細は [guide-calendar.md](guide-calendar.md)。複数局の時間軸は未移植。

## 更新と所有権

EPG取得・キャンセルは既存Acquisition enumが一つのJobを所有する。取得は5分間隔。
成功でスナップショットを置換し、失敗では以前のスナップショットを保持する。
無効化・接続先変更ではスナップショットを破棄する。32MiB／50,000番組の上限を維持する。

`presentation.rs` は選択局・revision・現在番組の識別情報だけを記憶し、本文や履歴を持たない。
同じ番組なら進行率だけを返し、本文をJSON化し直さない。revision変更時は同じ番組IDでも
説明の訂正を反映する。JSON化はResultで返し、UI境界で失敗を記録する。

`player/program_info.rs` が1秒間隔、または選択局・revision変更時に更新する。
通常のQtイベント処理の遅延を除き、番組の切り替わりは最大約1秒の粒度で追従する。
サーバーへ毎秒問い合わせることはない。システム時計が戻った場合も次回に選び直す。

`CurrentProgram.qml` は映像左上に局ロゴ・局名・番組名・時間を表示する。
main の左上24px、ロゴ64×36、番組名23pxの配置に合わせ、進行率は下部操作欄へ移した。
`ProgramDetails.qml` は現在の説明をスクロール表示し、放送由来の文字列はPlainTextとする。
[Qt Popup](https://doc.qt.io/qt-6/qml-qtquick-controls-popup.html)のOverlay中央配置を使い、
[ScrollView](https://doc.qt.io/qt-6/qml-qtquick-controls-scrollview.html)のcontentWidthを表示幅へ制限する。
詳細は開いている時だけLoaderで生成し、閉じた時とEPGを無効にした時に破棄する。
番組表を閉じていてもキャッシュから現在番組を選ぶが、詳細の文字配置・描画は行わない。

## 検証

Rustの試験: 番組境界・別局・重複除外・欠落／null・ゼロ時間・飽和加算・時計の巻き戻り、
進行率だけの更新でJSONを作らないこと、revision更新・選局・無効化での置換を確認する。
配信用IDとnetworkId/serviceIdが数値上対応しない局でも正しく照合し、明示メタデータがなければ
推測しないことも試験する。既存の取得失敗・キャンセル・更新間隔の試験も継続する。
EPGのテストは別ファイルへ移し、IOとスレッドの失敗はResultで返す形に変更した。

Qt Quick Testは実際の表示でタイトルボタンをクリックし、詳細表示・PlainText・番組変更時の
追従・局情報更新時の部品保持・Escapeによる破棄を確認する。
実行前にDISPLAY／GPUを検出し、xdpyinfoとglxinfoで検証する。

長期間のEPG更新・全機能併用・メモリー測定は別途必要。

2026-09-07の検証結果: Rust 46件成功（外部TS依存1件は未実行）、Clippy全ターゲット警告なし、
CMakeビルド成功。現在番組のQt操作2ケース、既存の選局3ケースが成功
（初期化・終了を含むrunner表示は9件）。CurrentProgram／ProgramDetailsはqmllint警告なし。

実サーバーでは15,266件を取得し、番組表を開かず「ニュース 『大雨』関連」、00:30〜05:00と
進行率が表示されることを画像で確認した。再生と正常終了に成功し、QMLエラーは出ていない。
EPG_MEMORYの保持量は3,046,078 bytes（Vec容量と文字列容量の合計）だった。
これはRSSではなく、長時間の増加を否定する測定でもない。
実機証跡はGit対象外の `benchmark/current-program/smoke.py`、`smoke.log`、`playing.png`。
実放送での番組境界をまたぐ待機と詳細の反復操作は未実施で、境界・詳細の検証範囲は上記自動試験。

## 視聴画面のデザイン移植状況

標準サイズをmainと同じ1440×900（最小900×560）にし、左上の番組情報と
右上の番組表・設定アイコン、上部グラデーションを移植した。接続先と機能切り替えは
設定ポップアップへ移した。これは中間実装であり、mainの設定ドロワー、番組詳細の
サイドパネル、音声選択、独自ウィンドウ枠、画面全体のアニメーションは未再現。
部品の操作試験と画面全体の外観一致は区別し、後者の完了とは扱わない。

下部はmainの丸形アイコン42px、間隔12px、左右24px／下22px、音量132pxと
下部グラデーションへ変更した。チャンネル一覧を開く際は130msでフェードし、
180msで20px移動する。停止後の再開手段を残すため再生／停止は状態で切り替える。
チャンネル選択はブラウザーへ集約し、前後の局への移動は既存PgUp／PgDownで行える。
診断・接続状況・設定エラーは設定内に表示する。字幕アイコンは有効な字幕機能の
表示を切り替える。再生設定アイコンは現在は共通設定を開き、mainの専用設定は未移植。

音量は[Qt Slider](https://doc.qt.io/qt-6/qml-qtquick-controls-slider.html)の
`moved`で操作を通知する。値の外部更新で操作通知を返さず、キーボード操作が
消音中も使えることをQtテストで確認した。新しいタイマーやRustの所有データは追加していない。
今回の検証はCMakeビルド成功、Qtテスト40件成功（初期化・終了を含む）、変更部品の
qmllint警告なし。実アプリの停止画面を画像で確認し、SVG読み込みと正常終了に成功した。
証跡はGit対象外の`benchmark/viewing-design/`。停止状態でEPG取得を待つ最初の試行は
取得条件を満たさず失敗したため、実データ付き表示の検証結果には含めない。
画面全体をmainと同じデータで比較する検証と、変更後の再生操作の実放送試験は未実施。
