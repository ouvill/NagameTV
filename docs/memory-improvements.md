# メモリ増加に対する改善（2026-09-06）

調査記録は `memory-investigation.md`。以下はその後に実装した改善であり、稼働中の旧プロセスの837MB前後というRESをすべて説明したものではない。

## 実装

- `epg_events.rs`: Mirakurunの開いたJSON配列をHTTPチャンク境界に依存せず解析。配列開始・空白を更新通知として扱わない。未完了イベントのバッファは1MiBまで。複数通知をまとめ、通知起因の全件取得は最短60秒間隔とする。最後の通知も、次の通知が来なくても送る。切断後には取りこぼしに備えて再同期を予約する。
- `network.rs`: 通常のHTTP要求は合計10秒の期限を維持。EPG通知は別クライアントで、接続5秒・レスポンスヘッダー待ち10秒、本文の合計期限なし。通信タスクの所有者を破棄すると待機中のIOもキャンセルする。
- `player.rs` / `epg.rs`: EPG全体のdeep cloneを除去。所有権をスナップショットへ移し、番組表はそこから必要なフィールドだけを複製する。更新要求は上限1件のキューでまとめ、取得中は次の通知をキューに残す。
- `comments.rs`: 処理待ちキューは256件、UIは1回64件まで処理。満杯時は新着を破棄してネットワークスレッドを止めない。コメント本文は4KiBまで、WebSocketメッセージ／フレームは64KiBまで。世代番号で古い接続のコメントを除外し、接続変更時には旧タスクをキャンセルする。接続と送信にも期限を設ける。
- 字幕: 再生時刻に沿った処理は継続し、最新の字幕画面だけを保持。非表示時はJSON生成とQMLの字幕部品生成を停止。再表示時にはその時点の字幕を反映する。
- QML: 番組表を閉じると番組カードのLoaderを無効化し、日別インデックス作成も停止。流れる実況は同時64件まで。非表示・選局時には動的部品を解放する。コメントはPlainTextで描画。

OSへの強制メモリ返却や定期的なmalloc_trimは追加していない。通常操作での長期的なRES/PSSの推移は引き続き確認が必要。通知による番組情報反映には最大約60秒の待ちが加わる。定期取得と手動更新は別に維持している。過負荷時は実況の一部が省略される。

## progenitor

- 公式: https://github.com/oxidecomputer/progenitor — OpenAPI 3.0.xからRustクライアントを生成。
- Mirakurun公式: https://github.com/Chinachu/Mirakurun/blob/master/api.yml — Swagger 2.0。
- 接続先の `/api/docs` もSwagger 2.0、38パスと確認した。リポジトリのapi.ymlだけではpathsが空なので、生成を行う場合はサーバーが公開する完成した仕様を取得し、3.0へ変換・固定する必要がある。

導入候補にはなるが、今回の修正では依存に追加していない。自動生成はAPIの型・呼び出しの保守を助けるものであり、更新頻度・ストリームの寿命・キュー上限を自動的に解決しない。導入時はまず通常のJSON APIに限定し、IDの整数精度・任意フィールド・既存reqwestクライアントとの互換性を検証する。

## 検証

Rustテスト51件成功、外部サービス等を必要とする既存の2件はignore。JSONの分割受信、複数イベント、上限超過、通知の集約、実況キューの上限・旧世代除外、タスクのキャンセル、10秒を超える通知本文の受信を含む。Releaseビルド成功。

実画面の検証は別プロセス・別設定ディレクトリで実施。元から動いている旧プロセスには停止・デバッガ接続・強制メモリ解放を行っていない。

映像・字幕・流れる実況の表示、番組表の再表示、字幕のOFF→ONを実画面で確認。サービスIDを毎回照合した京都／大津の高速切り替え20回では、RESは開始479.2MiB、途中448.7〜480.1MiB、10秒後497.1MiB。稼働時のスレッド40〜41、FD76〜77（選局待ち中は減少）。これは短時間の動作確認であり、旧版との条件を揃えたメモリ比較ではない。最初の自動操作試験には各選局の反映確認がなかったため、その398〜426MiBという値は選局負荷の評価には用いない。検証ログは `benchmark/memory-improvements-20260906/` に保存（git管理対象外）。

旧PID 50666は最後の確認では存在しなかった。こちらから終了操作は行っていない。検証用プロセス62206は確認後にウィンドウの閉じる操作で終了した。
