# UIデザイン方針

見た目の整い方に加え、操作したときの気持ちよさをアプリの品質として扱う。
細かなアニメーション、入力への反応、動きのつながりまで設計し、日常的に繰り返す操作を
軽快で心地よいものにする。この文書は今後の実装・調整・レビューの基準であり、
すべての画面で達成済みという記録ではない。

## 全体の方向性

映像を主役に、操作部は落ち着いた外観と明確な情報の優先順位を保つ。
既存の暗い背景、白系の文字、くすんだ緑のアクセントを基調とし、文字・余白・角丸・
アイコンの調子を画面間で揃える。選択中、押下中、フォーカス、無効状態を見分けられるようにする。

設定は、目的の項目を見つけ、現在値を確かめ、変更して視聴へ戻れる構成にする。
設定名と操作部で意味が伝わる項目には説明を足さない。常時表示する説明は、選択に必要な違い、
再生停止や履歴消去などの影響、操作できない理由に絞る。操作手順の繰り返し、内部の仕組み、
実装上の都合は画面に並べず、詳細な仕様は文書に残す。

情報のまとまりは配置と余白で示す。見出し、枠線、背景の囲みを重ねず、強調色は選択状態と
主操作に使う。補助操作は控えめな共通部品に揃え、機能追加のたびに新しい装飾を持ち込まない。

操作に応じた小さな変化を丁寧に作り込む。ボタンが沈んで戻る、つまみが指の動きに追従する、
選択枠が次の項目へ移るといった反応で、入力を受け取ったことと状態の変化が自然に伝わるようにする。
映像視聴中は動きを落ち着かせ、操作に関係のない反復や過度な移動で注意を奪わない。

## Penpotと実装の関係

Penpotを画面構成・配色・寸法・視覚的な方向性の参照にする。
各画面の参照先は[設定画面](settings-panel.md)、[コメント投稿欄](comment-posting.md)、
[録画操作部](recording-playback.md)などの仕様に記録する。

静止画の比較に加え、押す・離す・ドラッグする・切り替える・閉じるまでの一連の体験を確認する。
Penpotに表現されていない途中の状態や連続操作時の動きは、この方針に沿って設計する。
機能追加や操作性の改善でデザインとの差分が必要になった場合は、その意図と採用した振る舞いを
該当画面の仕様に残す。実装に差分があることだけを理由に、それを新しい基準にはしない。

## 動きと操作の手応え

- 入力への反応をすぐに返す。押下中の見た目は押した時点で変え、操作の実行や次の入力を
  アニメーションの終了待ちにしない。通信などの処理中は受付と完了を区別して伝える。
- 押し込み、戻り、切り替えの役割に合わせ、時間・移動量・拡大率・イージングを調整する。
  動き始めと収まり方まで確認し、同じ種類の操作には共通した手応えを持たせる。
- ドラッグ中は位置や値を入力に直接追従させる。補間によって手元から遅れる感触を作らない。
  シーク確定や保存のタイミングは各機能の仕様に従う。
- 連打、素早い切り替え、開閉途中の反転にも対応する。最新の状態へ自然につなぎ、
  古いアニメーションを順番に再生したり、開始位置へ不意に戻したりしない。
- 押し込みやホバーで見た目を拡大・縮小しても、クリックできる範囲を動かさない。
  キーボード操作でも状態の変化とフォーカス位置を確認できるようにする。
- 操作が終わったら動きも収まるようにする。描画負荷と映像再生への影響を確認し、
  装飾のためだけに常時動くタイマーや不要な描画資源を追加しない。

動きの値は`Theme.qml`に集約する。押し込み65ms、色の変化100ms、フェードイン120ms、
フェードアウト100ms、戻りや短い移動160ms、パネルの移動240msを基準とする。
時間が同じでも役割が違う値は別名で管理する。動く距離や部品の役割を変えるときは、
共通部品と部品一覧で反応を確認する。以前の調整記録は[操作への反応](ui-feedback.md)を参照。

## 共通部品と状態

同じ操作の外観と動きは共通部品へまとめる。色・寸法・動きの値は用途が分かる名前を付け、
同じ意味の値を共有する。個別画面だけの調整が必要な場合は、その理由を明確にする。

### 値・部品・画面の責務

| 管理する場所 | 責務 |
| --- | --- |
| [`Theme.qml`](../rust/qml/Theme.qml) | UIの色、文字サイズ、余白、角丸、無効時の濃さ、動きの基準。読み取り専用のQML singletonとする。 |
| 共通部品 | 通常・ホバー・押下・選択・フォーカス・無効状態の外観と操作。画面からは用途や状態を指定する。 |
| 各画面 | 配置、内容、表示データ、操作要求の接続。共通部品の`background`や`contentItem`を上書きしない。 |

共通値は`textPrimary`、`controlRadius`、`pressDuration`のように用途で名付ける。
似た色や寸法を画面名付きの値として増やさない。既存の値で表現できない場合は、
必要な用途を確認してから共通部品の種類を追加する。画面固有の幅・配置・番組表の時間軸など、
その画面で意味を持つ寸法は画面が所有する。

標準の文字サイズは注釈12、本文14、入力16、見出し18、画面タイトル24、開始画面のタイトル30とする。
10は時間軸やアイコン内の短い注記に限る。標準の操作高さは44、角丸は8、パネルの角丸は12、
無効時の不透明度は0.42とする。丸い操作部やつまみの角丸は、その高さから算出する。

### 共通部品の選び方

| 用途 | 使用する部品と指定 |
| --- | --- |
| 文字の操作ボタン | [`ActionButton`](../rust/qml/ActionButton.qml)。`emphasis`で`Primary / Secondary / Quiet`を選ぶ。音声・速度の選択肢は`selected`を元データから導く。 |
| 映像上の文字ボタン | `ActionButton`の`surface: ActionButton.VideoOverlay`。丸い形と半透明の反応を使う。 |
| アイコンの操作ボタン | [`IconAction`](../rust/qml/IconAction.qml)。裸のアイコンは`flat: true`、選択状態は`active`、閉じる操作の赤い反応は`emphasis: IconAction.Destructive`。 |
| 文字入力・選択・整数入力 | `SettingsField`、`SettingsChoice`、`ThemedSpinBox`。枠と背景は`ControlSurface`を共有する。 |
| 数値調整・切り替え | `ThemedSlider`、`ToggleSwitch`。設定の行には`SettingsSlider`、`SettingsToggle`を使う。 |
| 分割された選択肢 | `SegmentedControl`。外枠は`SegmentedFrame`を共有する。 |
| ポップアップ・カード | 背景に`PanelSurface`、チャンネルカードに`CardSurface`を使う。 |
| ツールチップ | `ThemedToolTip`。表示条件と位置は呼び出し元が指定する。 |

ボタンの押下では見た目だけを縮め、クリック領域は固定する。操作はアニメーション終了を待たずに
実行する。選択肢や現在値を共通部品の内部だけで確定せず、画面が受け取った状態から表示する。

番組表のジャンル色・時間帯色は情報を区別するため、[`GuidePalette.qml`](../rust/qml/GuidePalette.qml)で
管理し、明るいセルに対応する文字色もそこに置く。字幕・実況の描画色と影はコンテンツ描画側が所有する。
ライブ・録画のシークバーはバッファーや番組範囲の図形を持つため、`ThemedSlider`の背景を
置き換えてよい。`SettingsToggle`は共通のスイッチにラベルと説明を組み合わせるため、
行の背景と内容を定義する。これらの例外は静的検査にも用途とともに列挙する。

### 追加・変更時の確認

UI変更では、既存部品で表せるか、新しい種類が必要か、画面固有にする理由があるかを確認する。
共通部品や値を変える場合は、[部品一覧](../tests/ui-gallery/Controls.qml)と、それを使う主要画面を
通常サイズ・小さいサイズの両方で確認する。機能ごとのデザイン変更も、この共通基準へ反映する。

`python3 scripts/check-ui-style.py`は、UIの色コード・文字サイズ・角丸・アニメーション時間の
直接指定と、共通部品の背景・内容の上書きを検出する。CIでも実行する。この検査はQMLコンパイラーを
置き換えず、複雑な式や新しい独自部品まで外観の統一を保証するものではない。
構文・型・プロパティ参照は`bash scripts/check-qml.sh`で本体全QMLを検査し、
CIでは警告0件を必須とする。ビルドで生成した型情報を使う手順は[開発手順](development.md)を参照。

`bash scripts/test-ui-style.sh`は専用GUI環境で製品の共通部品を並べ、押下中のクリック領域、
無効時の操作抑止、キーボード操作、選択欄の開閉を確認する。画像は`build/ui-review/`へ保存する。
手順は[開発手順](development.md#テストと診断)を参照。

### 画面間で共有する構成

`SegmentedControl.qml`はPenpot「NagameTV · デザイン更新 2026-09-19」の
「ライブ / チャンネル選択」に合わせ、外枠の角丸を12px、選択枠とフォーカス枠を8pxとする。
放送種別、スクリーンショット形式、タイムシフト保存先の切り替えに共通で適用する。
外枠の色と角丸は`SegmentedFrame.qml`にまとめ、番組表の日付選択でも同じ形を使う。

視聴・番組表・設定の右上は`ModeNavigation.qml`を共用し、上端・右端から18pxの
位置にライブ・録画・番組表・設定、最小化・最大化・閉じるを同じ順序で並べる。
現在の画面だけを選択状態にする。設定から番組表を選ぶと番組表へ移り、設定の背後に
既に番組表がある場合もそのまま戻る。録画ファイルの選択をキャンセルした場合は
元の画面を保ち、開けた場合に視聴画面へ移る。

視聴用のサイドパネルは番組表では表示せず、番組表にウィンドウ全幅を割り当てる。
視聴へ戻った際はパネルの開閉状態と選択中のページを復元する。

表示と操作可否は実際の状態から導く。アニメーションの終了を業務上の完了として扱わず、
描画途中の値で操作結果を判断しない。排他的な状態や操作の前提条件は
[コード規約](coding-conventions.md)に従って表現する。

## ウィンドウサイズと表示倍率

初回は現在のディスプレイの作業領域の80%を目安に16:9サイズで開き、上限を1280×720、
通常の最小サイズを640×360にする。作業領域にはOSの表示スケーリングとタスクバーなどの
予約領域を反映する。作業領域自体が最小サイズより小さい場合は、その範囲に収める。
サイズはQtの論理ピクセルで指定し、ユーザーによるリサイズでは縦横比を固定しない。

2回目以降は終了時のウィンドウサイズを復元する。全画面・最大化・最小化中に終了した場合は、
通常表示時のサイズを保存する。ディスプレイ構成やスケーリングの変更で保存サイズが
現在の作業領域を超える場合は縮小して収める。保存先は既存の`settings.toml`と共通にする。

幅1280または高さ720を下回ると、表示倍率を`min(1, 幅/1280, 高さ/720)`で縮小する。
960×540では75%、640×360では50%になる。文字・ボタン・サイドパネル・番組表・設定・
ポップアップに同じ倍率を適用し、ウィンドウの縦横比が変わっても内容を引き伸ばさない。
映像・字幕・コメントも同じ座標変換を使う。リサイズ中は補間アニメーションを挟まず追従し、
ウィンドウ端のリサイズ操作領域は縮小しない。大きなウィンドウではUIの倍率を100%に保つ。

## 調整時の確認

見た目の比較と実際の操作を両方行う。通常の速度に加え、連打、途中での反転、
ドラッグ、キーボード操作を確認し、反応の遅れ、跳ね、ちらつき、クリック範囲のずれを確かめる。
小さいウィンドウと通常のサイズで、文字の読みやすさと動きの収まりも確認する。
映像の上に出る操作部は再生中にも確認し、視聴への影響を評価する。

変更の意図と確認した操作を記録する。静止画だけで動きの品質を確認済みとは扱わない。
検証手順と必要な機器の確認は[開発手順](development.md)と[専用GUIテスト環境](gui-test-environment.md)に従う。
