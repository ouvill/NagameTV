# mainへの置き換えに向けた開発方針

## UI再現の要件（2026-09-07追記）

ユーザーの指摘により、機能だけを実験用UIへ追加する進め方を修正する。
mainの見た目と操作性も置き換え要件に含む。配置、配色、文字サイズ、余白、アイコン、
角丸、パネル寸法、表示アニメーションをmainのQMLと同じ条件の画面比較で確認する。

未移植の設定・音声・実況等を動かないダミー操作として追加しない。

実装へ育てる。コード品質を重視し、機能追加に先立ってエラー・状態・所有関係を整理する。

## 設計の基準

- Qt/QMLは表示、入力、UI固有の状態を担当する。業務上の判断と資源管理はRustに置く。
- データ変換・判断は外部IOから切り離し、入力と結果で検証できるようにする。
- 状態と、その状態で許される操作を型で表現する。所有権を消費する遷移で
  不正な操作を防げるAPIには状態別の型を使う。非同期イベントで切り替わる状態は
  必要に応じてenumにまとめる。すべての状態を機械的に別型へ分けない。
- ネイティブ資源、通信Job、購読は所有者と終了手順を明確にする。キャンセル要求と
  完了確認を区別する。型で保証できる呼び出し順序と、実機で確認する外部状態を区別する。
- 読み取り中心のデータを共有し、必要な変更は所有者に限定する。関数型に寄せるために
  大きなデータを繰り返しcloneする設計にはしない。
- thiserrorで責務ごとのエラー型を定義し、原因のsourceを保持する。
  復旧判断はエラーの種類で行い、表示用文字列への変換はUI境界へ寄せる。
- 各機能は有効化・無効化・終了の契約を持つ。未使用機能の通信・購読・保持データを
  作らない。動的プラグインや共通traitは、具体的な必要性を確認してから導入する。

状態を型で表す設計の参考:
[Rust Book: Encoding States and Behavior as Types](https://doc.rust-lang.org/stable/book/ch18-03-oo-design-patterns.html#encoding-states-and-behavior-as-types)。
関数型／オブジェクト指向への統一ではなく、不正な操作を防ぎ、所有関係を追えることを基準とする。

## 現時点で整理する箇所と順序

1. **エラー型**：services・EPG・字幕開始処理の`Result<_, String>`、再生の
   `Box<dyn Error>`を整理する。HTTP途中再開拒否の復旧条件と回数制限を維持し、
   通信失敗・JSON解析失敗・上限超過を区別できるようにする。
2. **状態の表現**：EPGのjob/stopping/next等の組み合わせを見直し、取得中・取消し待ち
   などの状態と所有する資源を対応させる。旧リクエスト結果を受理しない契約を保つ。
3. **Qtとの境界**：Playerが担うQtプロパティへの変換と、再生・機能の制御を分ける。
   計算・判断はQtなしでテスト可能にする。小さな責務単位で変更する。
4. **機能移植**：mainの利用者向けの振る舞いを棚卸しし、機能単位で追加・検証する。

mainのREADME・モジュール一覧と現ブランチの設計書を確認した時点で、比較が必要な項目は
字幕の描画再現性、EPGの時間軸表示、実況、音声選択、ロゴ、設定保存、ウィンドウ操作等。
これは初期リストであり、機能互換性の網羅的な監査は未実施。
mainには既にQt非依存のviewer-coreもあるため、その契約・テストも評価対象とする。
既存実装の構造をそのまま移植することは前提にしない。

## 変更ごとの検証と置き換え条件

- 各整理は独立した差分とし、外部動作を変える変更と区別して記録する。
- ビルド、fmt、適切な静的検査に加え、状態遷移・取消し・失敗・終了の契約をテストする。
  実装をなぞるだけのテストを増やさず、過去のクラッシュや古い結果の混入を回帰条件にする。
- 再生・購読・終了に関係する変更は実機で停止再開、選局、機能ON/OFFを確認する。
  ハードウェアを使う前にはWorkshopの検出・動作確認を行う。
- mainを置き換える前に、対象機能の比較表を完成させ、差分と未対応を明記する。
  設定形式の互換性・移行方法も確認する。
- 長時間再生、複数回のEPG更新、字幕併用、番組表の開閉・スクロール、停止再開・選局で
  メモリーと資源数の推移を記録する。初期キャッシュの増加と継続的な増加を区別する。
  CPU負荷・フレーム落ち・起動や切り替えの応答も比較する。

現在の検証実績は[メモリー調査](allocator-investigation.md)等に記録されている。
glibc設定による短時間試験の改善は、全機能の長期安定性やmain置換の完了を意味しない。

## 整理の進捗（2026-09-07）

通信・EPG・字幕開始・再生の型付きエラーを導入し、EPGの取得状態をJobの所有関係と
一体にしたenumへ変更した。EPGのStatusは型で返し、表示文言はQt境界で生成する。
EPG解析からログ出力も分離した。詳細は [architecture.md](architecture.md)。
Player全体の分離は継続中。設定保存と起動時復元の移植を開始した。
機能ごとの現状と残作業は [feature-migration.md](feature-migration.md) を参照。
