## 録画番組の再生

2026-09-15に追加。以下はいずれも未着手です。

| 項目 | 実現したいこと |
| --- | --- |
| ローカルファイルの再生 | 録画したTSまたはMP4ファイルを再生する。 |
| ドラッグ＆ドロップ | 録画ファイルをアプリのウィンドウへ直接ドロップして再生を開始する。 |
| 録画サーバー連携 | サーバー上の録画番組を選んで再生する。最初の連携先候補は[stuayu/EPGStation](https://github.com/stuayu/EPGStation)。 |
| 再生位置・視聴状況の記憶 | 途中で閉じた録画を続きから再生する。視聴済み・未視聴も管理する。 |
| 録画番組の検索・整理 | 番組名・放送局・日付で検索し、同じシリーズの番組をまとめて表示する。 |
| 録画向けの再生操作 | 一時停止・再開・シーク、10秒戻し・30秒送り、倍速再生とキーボード操作に対応する。 |

現在の再生対象はMirakurunのライブ配信のみです。
EPGStation由来の実況チャンネル対応表は利用していますが、録画サーバーとの連携は未実装です。

この一覧で想定するEPGStationは、利用者が指定したstuayuフォーク版です。
録画再生・番組管理・予約連携は、このフォークのAPIを基準に調査・実装します。
対応するバージョンは実装前に確認します。

実装時には、再生位置と長さの表示、ライブ視聴との切り替え、
Mirakurunに接続していない状態でのファイル再生を設計します。
TSとMP4で対応する映像・音声形式や字幕の扱い、EPGStationの接続設定と再生方法は
実装前に確認します。

## 放送切り替え時の再生安定化

2026-09-15に報告。NHKの地方放送と全国放送の切り替え時に映像がフリーズすることがある。
原因は未確定で、現象を含むTSやログによる再現・検証が必要です。

- PIDやPMTの変更、ストリーム選択、時刻情報の不連続、受信エラーを調査する。
- [tsreadex](https://github.com/xtne6f/tsreadex)のようなサービス選択・PID固定処理の効果を、
  同じTSの処理前後で比較する。採用する方式は検証後に決める。
- エラー通知がなく映像が停止した場合の検出・復旧を検討する。

比較試験にはファイル入力の追加、または保存したTSを配信する検証用HTTPサーバーが必要です。
既存の自動復旧は特定のHTTP再開エラーに対するもので、このフリーズの解決確認にはなりません。
詳細は[ライブ配信の途中再開エラー](live-stream-errors.md)を参照してください。

### 不具合報告用の診断出力

2026-09-15に追加。既存の診断機能の改善候補です。

フリーズ前後の再生状態やエラーを、不具合報告に使いやすい形でまとめて保存できるようにします。

現在の記録方法は[メモリー分析と診断記録](memory-profiling.md)を参照してください。
