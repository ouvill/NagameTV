# STD-B24 実装対応リスト

最終確認: 2026-10-03。対象は NagameTV の現行コードである。ARIB STD-B24 は第1分冊の
モノメディア・字幕、第2分冊の BML/B-XML、第3分冊の伝送、さらにアプリケーション制御を
含む。`arib-b24` は現在、第3分冊のデータカルーセル受信と素材抽出を中心に実装している。
**STD-B24 全体への対応も、BML ビューワーへ渡す直前までの完成も、まだ達成していない。**

6.5 版と公開英訳 6.4-E1 の差分は未照合であり、この表は 6.5 版の全規定を
網羅した適合性判定ではない。

このリストでは「実装済み」を該当機能のコードと自動テストがあるもの、「一部対応」を
規格上の情報や動作の一部だけ扱うもの、「未対応」をコードがないものとする。
「別層」は表示・再生など、クレート外の責務を示す。実装済みの行も実放送での互換性確認を
意味しない。合成 TS・手製 section による回帰テストに加え、末尾に実放送で確認した範囲を記録する。

## BML ビューワー手前までに必要な作業

この節は、TS から選択サービスの BML 文書と参照素材を取得し、表示層へ一貫した状態で
渡すという当初の目標に対する残件である。第1・第2分冊の画面描画やスクリプト実行を
すべて `arib-b24` に入れるという意味ではない。

1. PMT と関連記述子から、コンポーネント・入口・プロファイル・データイベントの情報を型付きで公開する。
2. DII/DDB の規格上の変種と記述子を照合し、素材取得・有効化・更新・蓄積に影響するものを実装する。未知の拡張は生データで保持し、既知の未対応方式は明示的に報告する。
3. モジュール一覧、取得済み素材、更新・失効、データイベント、イベントメッセージを同じ受信世代で管理する。素材名の文字コードと URI の対応を定め、表示層が要求する素材を取得できるようにする。
4. NPT 参照と再生時計を対応付け、イベントの時刻指定を表示層へ渡す形式を決める。イベント実行そのものを表示層へ置く場合も、必要な時刻情報を失わない。
5. 代表的な実放送・録画 TS で、DII 更新、複数コンポーネント、遅れて届く素材、名前・文字コード、時刻付きイベントを確認する。初期画面の表示確認だけでは、番組更新・時刻付きイベント・全ページの操作まで完了したとは判定しない。

現行コードの起点は [`arib-b24`](../rust/crates/arib-b24/README.md)、
[`viewer-mpegts`](../rust/crates/viewer-mpegts/src/lib.rs)、
NagameTV の[字幕受信](../rust/src/features/subtitles/transport.rs)である。


## 2026-10-03 の互換性点検

公開英訳の第2分冊 §9.1.2・§9.3.4、第3分冊 §6.2 と、同梱する web-bml の
メッセージ定義を照合し、次を修正した。web-bml 本体のソースには変更を加えていない。

- 可視の起動文書にも開く操作を届ける。可視性だけで操作済みと判定しない。
- ModuleLocked やタイマーによる起動文書の遷移を待つ。公開 BML DOM で DataButtonPressed の購読を確認し、開く要求ごとに一度渡す。
- 文書と要求素材の読み込み完了と購読を確認後、1秒待って条件を再確認し、入力を渡す。
  NHK総合のように onload 後の短いタイマーで操作を有効にする BML への待機であり、規格上の準備完了保証ではない。
- DII の `return_to_entry_flag` を表示層へ渡す。
- PAT/PMT で確定した TS・サービス・PCR PID に従い、SDT/EIT/TOT の番組情報・放送時刻と PCR を渡す。
- HTTP エンティティのヘッダー順序・折り返しを処理し、直接対応かどうかを明示的な型で保持する。
  素材が1件でモジュール名と同名でも、エンティティの Content-Location を失わない。
- zlib の終端と検査値を確認し、末尾に追加された CRC32・ISIZE がある場合は両方を検証して受理する。
  KBS京都で観測した送出形式への互換処理である。zlib 本体は [RFC 1950 §2.2](https://www.rfc-editor.org/rfc/rfc1950#section-2.2)、
  追加の8バイトは [RFC 1952 §2.3.1](https://www.rfc-editor.org/rfc/rfc1952.html#section-2.3.1) の末尾形式に従う。
  不正な検査値・サイズ・未知の末尾データや途中で切れた圧縮ストリームは拒否する。
- PAT/PMT が確定し、BML の入口がない番組は「データ放送なし」と表示する。
  初期化用の空の PMT と実際の番組を区別し、入口の追加後には受信を継続する。
- 表示状態と映像矩形の通知を Qt WebChannel に移す。画面の破棄中に
  `runJavaScript` の結果コールバックが戻り、Qt 6.10.2 内で落ちる問題を修正する。

関西テレビの `/40/1FFF` と `/50/7000` は、採取時の DII に存在しなかった。
同局の起動 BML は未提供を表す ModuleLocked の status `-2` を処理しており、
これらの web-bml ログだけでは受信欠落を意味しない。起動時の複数段階の素材取得と遷移が
終わる前に d ボタンを渡していたことが、今回確認した表示停止の原因だった。
また、web-bml の `script execution timeout` は、同梱版の実装では50 ms実行した後に
一旦待機して再開する通知であり、このログだけでスクリプトが終了したとは判定できない。

カンテレの気象情報で繰り返される `getBrowserSupport pana dbgPrint` も、
メーカー拡張の対応状況を問い合わせ、非対応の `0` を返す処理だった。
これらの既知の照会結果と実行の一時中断は、同梱 JS からの出力に限って `DEBUG` とする。
WebEngine のコンソール通知を Rust へ渡し、出力元 URL と行番号を付けて記録する。
`RUST_LOG=info,web_bml=debug ./build/nagametv` で診断用ログも確認できる。
未知のエラー、NVRAM の必須情報不足、スクリプト例外は引き続き `ERROR` とする。
`unexpected streamStatus play` は、MNG の初期状態に関する web-bml の互換性警告として
`WARN` に残す。同梱版はこの通知後もアニメーションを開始するが、初期フレーム位置などの
互換性全体を保証するものではない。
修正後、カンテレの気象情報メニューから洗濯情報を開き、トップへ戻る操作を確認した。
この確認では `ERROR` と `[object HTMLElement]` の出力はなく、MNG の警告が1件残った。

### 確認方法と限界

Mirakurun の選択サービスを最大90秒受信し、専用 GUI セッションの画面画像、BML 文書 URL、
表示状態、映像矩形、受信ログを確認する。検証用 NVRAM は空のため、郵便番号が必要な
地域天気は未設定表示になる。[再現コマンド](development.md#テストと診断)は開発手順を参照。
初期画面とテレビ映像の確認であり、各ページの操作、投票・通信、Hybridcast、
番組境界や長時間の更新、物理スピーカーの出力はこの確認に含めない。
NPT と再生位置の同期など、上の表にある未対応項目は引き続き残る。
BS-TBS と BSテレ東では web-bml の `affiliationId == null!` ログも観測した。
表示の停止には至っていないが、系列共用 NVRAM の互換性を確認済みとはしていない。

## 2026-10-04 の起動・入力制御

公開英訳のTR-B14 6.7-E1 §2.1.10.1～4とSTD-B24 6.4-E1 §5.3.20.4・§5.4.13.4に
基づき、[起動・表示・操作の規定](data-broadcast-design.md#起動表示操作の規定)を実装した。

- データ放送の実験的機能を有効にしている場合、通常視聴中もPAT/PMTを監視し、入口の`auto_start_flag`が1ならBMLを起動する。機能全体は既定OFFで、[有効化の設定](data-broadcast-design.md#実験的機能の有効化)から変更する。
- 自動起動時にdを生成しない。実行中のdは`DataButtonPressed`として渡し、ページを破棄しない。
- `invisible`で非表示になっても実行を続ける。
- 表示中は`used-key-list`に従い、方向・決定・戻る、四色、数字のキー群を振り分ける。
  非表示で待機している間は、NagameTVの操作方針としてプレイヤーへキーを戻す。dの受付とBMLの実行は継続する。
- 可視の映像文書にも、フォーカス先・アクセスキーがなければプレイヤーへキーを戻す。
  入力先が後から変わった場合はDOMの変更通知で追従し、文書遷移中は直前の入力先を維持する。
- EscはBML操作中は戻るとして渡し、待機中はプレイヤーの通常操作に戻す。ブラウザーは保持し、設定のOFFで機能全体を停止する。

合成TSとBMLを用いた`startup -- data-broadcast`で、受信から表示・入力までの通し試験を実施した。
自動・手動起動、キー群の変更、dでメニューを閉じた後のタイマー継続、Esc後のブラウザー保持と設定OFFによる終了を確認した。
ABCテレビ1（サービスID `3272302072`）の実放送では、dでメニューから映像のみの文書へ
戻った後にBMLのキー受付が解除され、下キーでプレイヤーの操作部へ移れることを確認した。
文書が可視で`basic data-button`を保持していても、入力先がない場合の復帰を検証している。
その他の局や自動起動指定の変化を含む実放送での確認は残る。web-bml本体は無改変であり、
同ブラウザーのBML/CSS/API対応範囲や実放送の全ページを保証するものではない。
ARIB規格全体への対応完了を意味せず、上記の未対応項目は残る。
