# チャンネルブラウザーとロゴ

mainの画面下部のチャンネル選択を、独立したChannelBrowserへ移植する。
Cまたは「チャンネル」ボタンで開閉し、Escapeはブラウザーを番組表より先に閉じる。
表示中は操作部の自動非表示を抑止する。カードを押すと選局してブラウザーを破棄する。
矢印キーは一覧内のカーソルを動かし、Enterで選局する。
放送種別の変更だけでは選局しない。起動時は選択中の局の種別、未選択なら先頭局の種別を使う。

## データと描画の責務

Rustのservices wire modelからhasLogoDataを取り出す。未指定はfalse。
一覧取得時だけ作るQt向けRowにlogo URLを追加する。mainのrender.rsと同じく、
ロゴがある局だけ`/api/services/{id}/logo`を指定し、それ以外は空文字列。
u64の局IDをJavaScript数値に変換しない。URLにはRustで正確な10進文字列を埋め込み、
選局要求は既存の整数indexで返す。並べ替え後のindexと絞り込み後の位置を混同しない。

ChannelBrowserは既存のrows配列を受け、種別で絞った参照配列を表示する。
横方向ListViewで表示周辺だけカードを生成し、cacheBufferは0。
閉じるとLoaderが一覧とカードを破棄する。QtのImageは非同期取得、sourceSizeは128×72、
グローバル画像キャッシュは無効。繰り返し開く・スクロールする際の再取得と引き換えに、
訪問した全局の画像をアプリ側の長期キャッシュに保持しない。
ロゴ未取得・欠損・失敗時にはTVの表示を使い、選局機能は維持する。
sourceSizeは表示用画像のサイズ指定であり、HTTP受信サイズの上限ではない。

参照したQt API:

- [ListView](https://doc.qt.io/qt-6/qml-qtquick-listview.html)：必要時のdelegate生成、currentIndexとキーボード操作。
- [Image](https://doc.qt.io/qt-6/qml-qtquick-image.html)：asynchronous、sourceSize、cache、status。

## 開閉アニメーションと表示寿命

`AnimatedPanel.qml`はmainと同じOutCubic、移動240ms・フェード160msで開閉する。
閉じる操作では入力を直ちに無効化し、透明になった時点でLoaderを非アクティブにする。
Rustのbrowser_openも要求フラグではなくLoader.activeに追随させるため、フェード中に
番組名が消えることを防ぎ、非表示後はカードと番組表示用Projectionを破棄する。
閉じかけて開き直す場合は同じitemを維持する。アプリ終了はshuttingDownで即座に非アクティブ化し、
フェード完了を待たない。アニメーション時間を監視する追加Timerや遅延コールバックは作らない。
画面上部の外側クリックでも閉じる。閉じるアニメーション中はこのクリック領域も入力を取らない。

Qtの[Loader.active](https://doc.qt.io/qt-6/qml-qtquick-loader.html#active-prop)の
非アクティブ化時のitem解放と、[Behavior](https://doc.qt.io/qt-6/qml-qtquick-behavior.html)の
プロパティ変更に対するアニメーションを使用する。
実際のQtウィンドウで、フェード中のitem保持、途中再オープン時の同一item維持、
終了時の即時解放を作成・破棄カウンターで検証した。QMLスイート37件成功、ビルド成功。
実放送上での開閉・外側クリックとmainとの動画比較は未検証。

## 一覧を閉じた状態の前後選局

PgUp/PgDownはPlayer境界で±1をStep::Previous/Nextへ変換する。
それ以外の値は選局しない。ProgramInfoは共有Snapshotと操作時刻から同時放送を判定し、
元のカタログ順で前後の候補を返す。表示中の局が番組変更で非表示になった場合も、
その元indexを基準に前後を選ぶ。両端は循環し、空一覧では選局しない。
EPG無効／時計不明では各物理チャンネルの先頭を残す規則を使う。

候補を求める一時領域はキー操作時だけ生成する。ブラウザーProjectionやQMLの一覧を
常駐させず、EPG全件の複製・JSON変換・追加の通信やTimerも行わない。
候補確定後は既存のselect経路で再生する。

検証では前後・循環・非表示の選択局・空一覧に加え、実際のSnapshot検索を使って
番組境界で候補が変わることを試験する。外部xdotoolのPgDownでは再生開始を確認できず、
実アプリのキーボード入力から再生までの結合確認は未完了。
サーバー停止だけを原因とは断定しない。Qt Testのキー配送とRustの候補計算を分けて記録する。

この変更の検証結果はRust53件成功・外部TS依存1件未実行、Qt59件成功、
Clippy全ターゲット警告なし、releaseビルド成功。DISPLAY・NVIDIA OpenGL・PulseAudioを
確認後、実サーバーのサービス一覧HTTP 200、実アプリのEPG取得と正常終了を確認した。

## タッチパッドのスクロール量（2026-09-19）

下部の候補移動とサイドパネルのスクロールは、`ChannelScrollArea.qml`で入力の距離を
共通処理する。以前の「イベント1回につき1候補／144px」では、タッチパッドや
高解像度ホイールの小さな連続入力も毎回大きな移動になっていた。

[QtのWheelEvent仕様](https://doc.qt.io/qt-6/qml-qtquick-wheelevent.html)に従い、
`pixelDelta`があれば優先し、なければ`angleDelta`の120単位をホイール1段として扱う。
縦横のうち絶対値が大きい軸を一つだけ使う。方向はOSから受け取った符号を維持する。
タッチパッドも同じ入力領域で受け、下のListViewと二重に処理しない。

- 下部は候補カードの幅＋間隔のピクセル移動、またはホイール1段で1候補移動する。
  小さな入力は累積し、方向反転・単位変更・250msの入力休止・開き直し・候補一覧の
  更新・左右キー操作で端数を捨てる。複数段がまとまったイベントも移動量に反映する。
  スクロールだけでは選局せず、既存の中央寄せアニメーションと確定操作を維持する。
- サイドパネルはピクセル入力をその距離だけ移動し、角度入力は1段144pxに比例させる。
  従来どおり慣性移動を止め、`originY`を含む一覧の範囲内へ収める。

`scripts/test-channel-wheel.sh`で細かな角度入力、横方向、複数段、方向反転、入力休止、
開き直し、一覧の両端、カードへのクリック伝播を確認する。
Qt Quick Testの`mouseWheel`はピクセル入力を指定できないため、ピクセル優先・移動量・
斜め入力の試験は同じ入力処理関数へ直接渡す。物理タッチパッドやOSからのピクセル
イベント配送、実機での操作感を確認したものではない。

専用のXwayland・実GPU環境でスクロール試験11件、既存の下部／サイドパネル試験20件
（初期化・終了を含む）が成功。変更したQMLのqmllintは警告なし、CMakeのreleaseビルドも成功。

## 次番組の表示

下部と右側のチャンネルカードは、現在番組の時刻の下に次番組の開始時刻とタイトルを
11px・1行で表示する。長いタイトルは末尾を省略し、番組情報がない場合は行を隠す。
共有EPGから同一サービスの現在時刻より後に始まる最初の有効な番組を借用し、
タイトル・開始時刻・長さのみをJSONへ投影する。説明文はコピーしない。
番組境界・EPG更新・EPG無効化で表示を更新し、現在番組の進捗表示は維持する。

## 番組表の日付変更時の表示

日付変更では共有EPGからその場で表示用JSONを作り、同じUIイベント内で置き換える。
従来の「空配列へ変更して次のpollで再表示」は行わないため、空の背景を描画する
待ち時間を挟まない。通常のEPG更新と同じ投影処理を使用し、日付別キャッシュは持たない。
切り替え中は新旧の表示用データが一時的に重なるが、古い日付をアプリ側に保持しない。
Qtのオブジェクト破棄・GCやアロケーターによる実際のメモリー回収時期は別であり、
RSSの増減やピーク値は未計測。
