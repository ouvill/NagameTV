# データ放送の受信と表示の設計

## 実験的機能の有効化

`data_broadcast_enabled`は既定OFFの実行時フラグである。
「設定 → 表示 → データ放送を有効にする（実験的）」で変更する。
従来の先読み設定がONでも、このフラグがない設定ファイルでは機能全体をOFFとして読み込む。

OFFの間はデータ放送用の受信ワーカー・loopback接続口・WebEngineViewを作らず、
データ放送用のPAT/PMT監視、素材の受信、自動起動、d入力を停止する。
通常再生で必要なTS解析と字幕・実況処理は継続する。
再生中のON/OFFは同じTS入力へ適用し、再生やMirakurunへの接続をやり直さない。
受信先の変更は最新の要求だけを再生側へ渡す。録画URLを読むReaderのロックを
UIスレッドで待たず、OFFでは受信ワーカーの停止によって古い受信先も即座に無効になる。
OFFへの変更はブラウザーと受信資源を解放し、開く意図も取り消す。先読みの設定値は保持する。
再度ONにすると入口を検出し直し、放送の自動起動指定に従う。

`playback::session::broadcast`が入力ごとの利用可能性と受信資源を所有し、
受信状態を`Disabled` / `Running` / `Failed`で表す。
受信の初期化失敗は通常再生へ伝播せず、操作と原因をログに記録する。
`Failed`では定期的な状態更新による再試行を行わず、OFF→ONまたは入力の変更で再試行する。
Qtへの変更通知は、設定・受信資源・開く意図・接続先を更新してから行う。

検証用の`--features=data-broadcast`では一時設定で有効にする。データ放送を含まない
機能制限ではUIからも有効化できない。Qt WebEngineのビルド・配布依存はOFFでも残る。
フラグの運用と実験扱いの解除条件は[開発ガイド](development.md#トランクベース開発とフィーチャーフラグ)に定める。

## 所有者

以下の受信・起動・操作は、機能全体が有効な場合に適用する。
受信セッションは再生セッションに属する。ブラウザーは受信状態の購読者として接続する。
BMLを実行している間は、文書が非表示になった場合やブラウザーの接続が途切れた場合も受信を続ける。
通常視聴中はPAT/PMTを監視し、入口の`auto_start_flag`が1ならWebEngineを自動起動する。
自動起動ではd入力を生成せず、起動文書の表示とイベント処理に従う。
「設定 → 表示 → データ放送を先読み」は、自動起動も明示的な起動もされていないライブ視聴での
素材保持を切り替える。初期値はオフで、`data_broadcast_prefetch`に保存する。
録画の先読みは行わないが、TSの自動起動指定は読み取る。

## 起動・表示・操作の規定

視聴画面のサイドパネルにある「リモコン」タブで、データ放送を操作する。
d、方向、決定、戻る、青・赤・緑・黄、数字0〜9をパネル内に表示する。再生操作部と
「…」メニューにはデータ放送ボタンを置かない。機能が無効、または再生対象がデータ放送に
対応していない場合はタブを表示しない。操作中に利用できなくなった場合は「視聴設定」へ戻る。

方向・決定・戻る・四色・数字は、表示中のBMLが受け付けるキー群に合わせて有効にする。
待機中はdから再表示できる。パネル内にフォーカスがある間は方向キーでボタンを選び、
Enterで実行する。十字キー・四色キー・数字キーを縦に並べ、収まらない場合はフォーカスに
合わせてスクロールする。リモコン内の「戻る」はBMLへ送り、Esc・キーボードの戻る・右上の
閉じるボタンはサイドパネルを閉じる。パネルを閉じてもBMLの実行は継続する。

リモコンの部品操作は`python3 scripts/test.py danmaku`、BMLへの入力と待機・再表示は
`python3 scripts/test.py startup -- data-broadcast`で確認する。後者は通常サイズと最小サイズの
画面画像を`build/navigation-review/data-remote-1280.png`と`data-remote-640.png`へ保存する。

公開英訳の[TR-B14 6.7-E1 第3編第2部](https://www.arib.or.jp/english/html/overview/doc/8-TR-B14v6_7-2p5-E1.pdf#page=80)
§2.1.10.1～4を起動とdボタンの基準とする。自動起動フラグが1から0に変わっても実行を継続し、
入口が消えた場合は実行を終了する。dボタンは実行開始後にBMLへ渡し、エンジンの破棄には使わない。
フラグ0の初回d操作はエンジン起動に使うため、起動文書へ重ねてdイベントを送らない。

[STD-B24 6.4-E1 第2分冊](https://www.arib.or.jp/english/html/overview/doc/6-STD-B24v6_4-2p3-1-E1.pdf#page=49)
§5.3.20.4に従い、`invisible`は表示のみを切り替える。§5.4.13.4の`used-key-list`を
web-bmlの公開イベントとBML DOMから取得し、指定されたキー群だけをBMLへ渡す。
未指定なら`basic data-button`、`none`なら受付なしとして扱う。dボタンのイベント通知は別経路である。
これらはリモコンのボタンの有効条件に使い、キーボードショートカットには適用しない。

NagameTVでは、方向・決定・戻る・四色・数字・Dを含むキーボード入力をBMLへ直接渡さない。
表示中も待機中もWebEngineはフォーカスを取得せず、キー操作はアプリの画面移動や再生操作に使う。
BMLへの入力はリモコン上のボタンの実行から送る。非表示の待機中はd以外を無効にし、
BMLの実行とdイベントの受付は継続する。文書遷移中は直前のボタンの有効条件を維持する。

可視の映像文書でも、フォーカス先とアクセスキーがともに存在しなければ、d以外のリモコン操作を
無効にする。ABCの実放送では、dで閉じた後の映像専用文書に既定の`basic data-button`が
残っていた。`used-key-list`はそのまま保存し、入力先の有無を別の`inputAvailable`として通知する。
文書名・局名・映像の大きさから開閉を推測しない。
公開APIの`getVideoElement()`から得たDOMの変更を監視し、タイマーなどによる
フォーカス先やアクセスキーの追加・削除にも追従する。入力可否が変わったときだけ
通知し、定期ポーリングは行わない。文書遷移中は直前の入力可否を維持する。
Cプロファイルは方向キーで最初のフォーカスを取得できるため、この抑制を適用しない。
映像要素がなくDOMを観測できない文書も、従来のキー指定に従う。

Escとキーボードの戻るキーは、BMLの表示状態にかかわらず、プレイヤーの前面の画面や
操作部を閉じる。閉じる対象がなければEscは全画面を解除する。
Escからブラウザーの終了や自動起動の抑止は要求しない。機能全体の停止は設定のOFFで行う。
ブラウザーや受信処理の失敗時は、その視聴中の自動再試行を抑止して再起動ループを防ぐ。
WebEngineの常駐を避ける以前の方針は、自動起動指定のある放送には適用しない。

| 対象 | 所有者 | 責務 |
| --- | --- | --- |
| TS、PSI、DSM-CC、素材の構文 | `viewer-mpegts` / `arib-b24` | 規格の解析、再構成、エラーの報告 |
| 開く・閉じる要求 | RustのPlayerアダプター | `data_broadcast::Mode`で視聴対象に結び付け、再生セッションに反映。QMLへ状態を公開 |
| 受信の状態と寿命 | `features::data_broadcast` | `Closed` / `Receiving` / `Failed`、入力世代、デコーダー |
| 受信と表示の要求 | `data_broadcast::Demand` | `Stopped` / `Monitor` / `Prefetch` / `Display`。監視・先読み中はブラウザーの購読を許可しない |
| 再接続用の最新状態 | `data_broadcast::snapshot` | 型付き更新の保持と失効。web-bmlの内部状態を参照しない |
| web-bmlへの変換 | `viewer-web-bml` | 公開メッセージ形式への変換。Qtや通信処理を含めない |
| 接続と配信 | `data_broadcast::delivery` | スナップショットと差分の順序、有限キュー、書き込み期限 |
| ブラウザーの接続状態 | `assets/web-bml/session.js` | 接続プロトコルと受信世代の検証 |
| BMLの表示状態 | `presentation.js` | 起動待ち、表示、遷移、待機、入口なし |
| BMLの入力先の観測 | `input.js` | キー指定と、映像文書内のフォーカス先・アクセスキーの有無 |
| 起動時の互換性処理 | `activation.js` | 公開APIで確認できる条件を待ち、要求ごとに一度dを送る |
| レイアウトと入力先 | QML | 映像矩形、フォーカス、キー配送、WebEngineViewの寿命 |

QMLが保持する表示状態と映像矩形はブラウザーから届く投影である。
開閉要求をQMLでも別に書き換えたり、WebEngineの読み込み完了を受信開始の条件にしたりしない。

## 操作と状態遷移

| 操作・通知 | 受信側 | 表示側 |
| --- | --- | --- |
| 自動起動指定 | PAT/PMT監視から素材受信へ移る | ページを作り、d入力を生成せず起動文書を実行 |
| d（未起動） | 素材受信開始。先読み済みなら保持状態をそのまま渡す | 自動起動指定の有無に従い初回d入力を扱う |
| d（起動済み） | 受信継続 | BMLへDataButtonPressedを渡す。ページを破棄しない |
| BMLで戻る | 受信継続 | BackspaceをBMLへ渡す。BMLが非表示にしたら待機へ移る |
| 待機中にd | 受信状態を保持 | 同じページへDataButtonPressedを渡す |
| Esc | 受信継続 | BML操作中は戻るを渡す。待機中はプレイヤーの通常の閉じる操作を行い、ページを保持する |
| 設定でデータ放送機能をOFF | 受信・購読・素材保持を終了 | ページを破棄し、入力をプレイヤーへ戻す |
| 別チャンネルへ選局・録画ファイルを開く | 開く意図を解除し、旧セッションを破棄。新しい局では設定に従って先読み | 待機中も含めてページを破棄。新しい視聴対象の自動起動指定に従う |
| 明示的な再生停止・接続先サーバー変更 | 開く意図を解除し、受信終了 | ページを破棄。次の再生へ開く意図を持ち越さない |
| 同じチャンネルへの再接続 | 開閉の意図を保持。受信セッションを再構築 | 有効なら新URLで起動文書から再開する |
| 同じチャンネルの番組更新 | 受信継続。番組情報と放送イベントを配信 | ページの遷移はBMLに従う |
| シーク・入力リセット | 受信世代を更新し、デコーダーと保持素材を破棄 | ページを再読み込みして再同期 |
| ブラウザー切断・送信の遅延 | 購読者だけを切り離し、受信継続 | 接続を失ったら1秒後にページを再読み込み |
| TSキュー超過・保持状態の構築失敗 | `Failed`へ移り、理由をログと制御通知に出す | 自動再試行せず、開き直しを案内 |

先読み設定の変更は視聴中にも反映する。データ放送を開いている間は、設定をオフにしても受信を継続する。
BMLを実行していない間にオフにすると、素材の受信を停止して保持データを破棄し、PAT/PMT監視を続ける。先読みの失敗はバックグラウンドで繰り返し再試行せず、
利用者が開いたときに受信を再開する。先読みから表示への移行で受信世代を変えず、デコーダーを作り直さない。

受信元は再生用Readerと共通で、別のMirakurunストリームは作らない。シーク時は保持状態を破棄し、再生位置の異なる素材を混ぜない。
先読み中も保持量の上限とモジュールの版変更・削除による失効を適用する。短縮するのはカルーセルの待ち時間であり、
WebEngineのページ生成とBMLの初期化、未受信素材の待ちは残る。

開く意図はRust側で視聴対象に結び付ける。同じ局の再選択、一時停止、番組更新では解除しない。
録画はファイルを開き直した時点で新しい視聴とする。検査に失敗して元の視聴が続く場合はモードを維持する。
停止中の開く要求は受け付けず、次の視聴で意図せず起動しないようにする。

ブラウザーだけの再接続では放送素材を引き継げるが、実行中のBMLスクリプトや閲覧ページまでは復元しない。
新しいページで起動文書から開始する。まだ配送していないd要求だけを引き継ぎ、
画面の可視性を理由にdを再送しない。天気の重畳表示が残っていても、メニューが開いているとは限らない。

## 小窓の映像と重ね合わせ

BMLの映像矩形は、Qtの`videoViewport`へ適用する。その中にGStreamerの映像、
ARIB字幕、通常メディアの字幕、実況コメントを置き、移動・縮小とクリッピングを共通化する。
BMLはこの領域より上で描画し、web-bmlが開けた映像の透過窓から重ね合わせ済みの映像を見せる。
BMLを閉じたときは同じ領域を通常の映像サイズへ戻す。

実況コメントは小窓内の実際の映像範囲を使い、文字サイズもその高さに比例させる。
番組名や操作部との重なり判定には小窓の位置を含める。ARIB字幕は字幕面の座標を小窓へ縮尺変換し、
座標を持たないテキスト字幕も文字サイズと余白を映像の高さに合わせる。

## 接続プロトコル

loopbackのランダムURLへ接続すると、バージョン1の制御メッセージを送る。
`begin(version, epoch)`、`update(epoch, message)`の列、`ready(epoch)`の順で初期状態を渡し、
以降は同じ世代の`update`を送る。世代はJavaScriptの数値精度に依存しない文字列とする。
`message`にはweb-bmlの既存形式をそのまま入れ、JSアダプターが`BMLBrowser.emitMessage`へ渡す。

受信をリセットした場合は新世代の`begin`を送る。JSは古いページへの適用を止め、QMLに再読み込みを要求する。
初期化のための架空の空PMTは送らない。実際のPAT/PMTに由来する更新だけを放送情報として扱う。
`fault(reason)`は受信セッションの停止を表す。通信切断と区別し、再読み込みを繰り返さない。

スナップショット作成と差分の登録は単一の受信処理で順序付ける。
接続処理へは`Arc`で共有した更新を渡し、素材の複製とBase64化は受信処理に持ち込まない。
購読開始時には番組情報、放送時刻、PCR、BIT、PMT、全コンポーネントのDII、完成素材の順に渡す。
全DIIを素材より先に送ることで、起動直後の別コンポーネントへの照会にも受信済み一覧を使える。
過去のイベントメッセージは再送せず、接続後に届くイベントを配信する。

### 保持と失効

- PMTから削除・変更されたコンポーネントのDIIと素材を削除する。
- DIIのdownload ID、モジュールの版、サイズ、記述子が変わった素材を削除する。
- DIIから消えたモジュールを削除する。
- 複数モジュールの連結素材は、末尾を含む全構成モジュールの変更で失効させる。
- シーク、受信要求が`Stopped`になった場合、再生セッションの破棄で全状態を破棄する。

入力キューは最大4 MiB、購読者へのキューは最大32件、各WebSocket書き込みの期限は250 msとする。
保持素材の合計予算は64 MiBで、素材本体・名前・媒体型を数える。
送信待ち・書き込み中の素材には別途64 MiBの共通予算を設ける。接続が置き換わっても、旧接続の書き込みが終わるまで予算を返却しない。
送信予算の超過では購読者だけを切り離す。この値はアプリの保持方針であり、
STD-B24が定めるモジュール上限ではない。受信状態の保持予算を超過した場合はエラーとして通知する。
送信中のスナップショットは更新前の素材を参照し続ける場合があるため、この予算はプロセス全体のメモリー上限ではない。
TS再構成用の領域、送信用JSON・Base64、web-bml・WebEngineの領域も別に必要になる。

## メモリーと反復処理

TS入力は完全な188バイトのパケットを入力バッファーから直接解析し、次の入力へまたがる
端数だけを固定長バッファーに保持する。セクション受信の重複確認にも固定長領域を使い、
パケットごとのヒープ割り当てを避ける。同一世代のDIIの再受信では既知モジュールの受信用領域を
作り直さず、新規モジュールだけを検証して追加する。競合するDIIは受信途中のデータを変更せずに拒否する。

配信時は`viewer-web-bml::prepare`で変換可能性を検査してから、素材を借用するメッセージを
送信先のJSONバッファーへ直列化する。Base64文字列をJSONツリーの各階層で複製しない。
送信形式は従来と同じで、受信状態の共有と送信予算の寿命も維持する。

表示状態・映像矩形・受付キー群は、状態変更、web-bmlの`videochanged`と`usedkeylistchanged`、
ウィンドウのサイズ変更を契機に通知する。
一連の同期処理による通知はまとめ、前回と同じ値ならWebChannelへ送らない。
アダプターによる100ms周期のDOM測定・JSON化は行わない。放送側BML自身のタイマーはこの対象に含まない。

2026-10-04に変更前後のコードを同じreleaseビルドで比較した。4MiBの素材1個を含む送信JSONの生成は、
処理時間が約15.9msから5.1ms、追加ヒープ使用量のピークが約21.3MiBから10.0MiBになった。
時間は8回の処理を5組測った中央値、メモリーは別実行で割り当てを数えた値である。
素材本体は測定開始前に用意し、ネットワーク送信とブラウザーの受信・描画は含まない。
この測定値はアプリ全体の使用メモリーや表示時間を表すものではない。

## 互換性処理の範囲と撤去条件

待機中もWebEngineView自体は可視状態を保ち、Qtの不透明度と入力の有効・無効で画面を隠す。
web-bmlは文書読み込みで`requestAnimationFrame`を待つため、Viewを非表示にして描画フレームを
止めると、d操作や放送イベントによる次の文書への遷移も停止し得る。設定で機能をOFFにしたときはViewを破棄する。

upstreamのweb-bmlは固定コミットを無改変で使う。局名による分岐や内部フィールドの操作を追加しない。

| 処理 | 根拠・現在の限界 | 撤去・変更の条件 |
| --- | --- | --- |
| 起動入力の1秒待ち | 公開の読み込み完了後にも初期化タイマーが動く起動文書がある。完了の保証にはならない | upstreamに入力を受理できる状態の公開通知ができ、NHK・BSの起動試験を通せること |
| BML DOMの逆順走査 | 固定版が合成した`arib-script`のラッパー作成時にエラーを出す | upstreamのラッパーが修正されるか、公開の購読照会APIができること |
| ページ全体の再読み込み | 現在の`destroy()`はインタープリターのタイマー・待ち処理を終了しない | 全処理の終了を保証する公開APIと、その回帰試験ができること |
| `opacity`と`inert`による非表示 | 非表示文書でも次の映像透過窓を測定するため、レイアウトを維持する必要がある | upstreamの映像プレーン計算が非表示レイアウトに依存しなくなること |
| 既知ログの分類 | 未提供モジュールや非対応機能の照会結果が固定版では`console.error`になる | upstreamのログレベルまたは公開診断APIが改善されること |

起動の1秒待ちは`activation.js`に隔離する。文書遷移・接続切断・要求取消で待ちを取り消し、
定期的にdを再送しない。長い初期化中に入力を捨てるBMLには、利用者の再操作が必要な場合がある。
MNG互換性や長時間初期化の問題は、この責務分離だけでは解消しない。

## 検証

機器不要の試験は`python3 scripts/test.py app --filter 'test(data_broadcast)'`、

GUI試験は[専用の検証環境](gui-test-environment.md)を使う。
起動文書の即時表示・不可視待機・素材待ち・タイマー遷移・入力初期化待ち、映像の透過窓、
